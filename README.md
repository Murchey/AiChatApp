# AiChat

> 📖 **English Version** — [README_FILES/README_EN.md](README_FILES/README_EN.md)

一款**角色扮演类微信聊天风格**的 Flutter Android 应用：内置多个角色，可与角色进行一对一的沉浸式聊天（支持发送图片、合并转发、角色包导入导出、自动更新等）。

> 纯 Cupertino（iOS 风格）UI，仅适配 Android。

## 功能特性

### 核心聊天
- **沉浸式角色聊天**：内置多个角色（人设、说话风格、核心记忆），支持自定义人设与用户关系
- **合并转发**：多选消息合并转发为卡片，独立展示并显示我方头像
- **图片消息**：通过「API 设置」中添加的模型发送图片（需模型支持视觉）
- **Markdown 渲染**：AI 回复支持 Markdown 格式渲染（代码块、列表、表格等）
- **聊天气泡样式**：默认/崩铁/鸣潮/终末地四种气泡样式可选，支持自定义气泡颜色与字体颜色
- **聊天背景**：为每个会话设置独立的背景图片，支持高斯模糊度调节
- **聊天搜索**：在聊天记录中搜索关键词
- **联系人搜索**：在通讯录中搜索角色
- **消息引用**：长按消息可引用回复

### 群聊功能
- **多角色群聊**：创建包含多个角色的群聊，角色之间可相互对话
- **@ 角色**：在群聊中 @ 特定角色，被 @ 的角色必定发言
- **引用回复**：角色发言时可引用其他成员的消息进行回复
- **群头像**：支持自定义群头像，未设置时自动生成成员拼图头像
- **群简介**：设置群聊简介，角色会按简介语境进行对话
- **不说话概率**：配置角色在群聊中的沉默概率（0~1），默认 0.2
- **引用回复概率**：配置角色发言时引用其他消息的概率（0~1），默认 0.2
- **群聊上下文**：群聊可独立设置上下文条数，或跟随全局设置
- **未读消息**：群聊支持未读消息计数，离开群聊页面时累计新消息

### 角色包与创意工坊
- **角色包导入/导出**：`.zip` 角色包一键导入、导出，支持批量勾选
- **创意工坊**：从 GitHub/Gitee 仓库下载角色包和游戏包
  - 支持添加多个仓库，自动检测可用的 Release tag
  - 角色分类（V1.1.0）：包含 Profile.json 的角色文件夹 zip
  - 游戏分类（V1.0.0）：包含 moments.json 的朋友圈数据包
  - 更新通知（V1.2.0）：接收仓库更新通知
  - 支持 GitHub 下载代理加速
- **朋友圈数据包**：**【我】→ 管理当前朋友圈** 导入/导出角色的朋友圈数据包，支持勾选导出

### 记忆系统
- **持久化记忆**：长按聊天气泡批量保存为记忆点，随角色的系统提示词一起发送给模型（聊天与朋友圈互动均生效）；记忆随角色包导入 / 导出（写入 Profile.json）
- **记忆池（跨场景记忆）**：聚合角色在「当前会话之外」的近期记忆，让角色在私聊/群聊/朋友圈互动中保持跨场景的记忆连贯
  - 近期私聊内容
  - 近期朋友圈（最近 N 条贴文 + 全部点赞与评论）
  - 近期群聊内容（该角色参与的、最近有消息的群，每群最近 3 条文本消息）
  - 角色资料卡（昵称/关系/备注/签名/地区/性格/介绍/开场白/标签）
  - 用户资料（昵称/性别/地区/签名）
- **记忆池管理**：可按角色独立停用记忆池的各个来源

### 朋友圈
- **朋友圈互动**：用户发布朋友圈后，可见范围内的角色会自动点赞/评论
- **自动发朋友圈**：角色可按设定的周期自动生成并发布朋友圈内容
  - 可配置发布周期（小时）、周期内发布条数
  - 可设置朋友圈可见范围
  - 应用启动/回到前台时检查并补发布
- **朋友圈互动通知**：角色点赞/评论产生未读通知，朋友圈 tab 显示红点
- **朋友圈可见性分组**：自定义朋友圈可见范围分组
  - 仅自己可见
  - 全部角色可见（默认）
  - 自定义分组（选择特定角色）
- **朋友圈管理**：导入/导出朋友圈数据包

### 主动问候
- **主动问候**：角色在用户一段时间未聊天后，会主动发送问候消息
  - 可配置无消息多少小时后触发问候（默认 72 小时）
  - 应用启动/回到前台时检查并触发

### API 与模型
- **上下文管理**：设置携带上下文条数（1 ~ 999 条，或「无限制」），可精确输入
- **会话自动压缩**：上下文无限制时自动开启压缩，达到所选模型上下文阈值（可调）时自动把更早的历史消息压缩为摘要
- **厂商预设**：内置多个 AI 厂商配置预设（OpenAI、Google Gemini、小米 MiMo 等）
- **模型检测**：支持一键检测可用模型列表
- **Token 消耗统计**：记录各会话（私聊/群聊/朋友圈互动）的累计 token 使用量

### UI 与个性化
- **明暗模式**：跟随系统 / 浅色 / 深色，可自定义主题色
- **气泡样式**：默认/崩铁/鸣潮/终末地四种气泡样式可选
- **UI 样式**：默认/终末地两种 UI 样式可选
- **气泡颜色自定义**：可分别设置自己/对方 × 浅色/深色的气泡颜色和字体颜色
- **头像框样式**：方形 / 仿 QQ 圆形两种头像框样式
- **启动图标**：自定义应用启动图标
- **聊天背景**：为每个会话设置独立的背景图片和模糊度

### 其他功能
- **自动更新**：启动时自动检测新版本（Gitee 优先、GitHub 备用双源），更新弹窗可选下载源，一键下载并安装 APK
- **聊天记录导出/导入**：支持将聊天记录导出为 zip 包（包含文本、图片、文件），可导入恢复
- **存储空间管理**：管理应用占用的存储空间（用户数据/软件缓存），支持清理
- **开发者日志**：开发者模式下可查看实时日志（朋友圈 AI 互动日志、软件通知、错误信息等）
- **系统通知**：角色在用户离开聊天界面时发来新消息，向系统通知栏推送通知（包含角色名称、消息内容与头像）
- **图片裁剪**：发送图片前支持裁剪

### 数据自主权
- **角色包导入/导出**：一键导出角色包（`.zip`），包含角色资料、提示词、头像、朋友圈、记忆点等全部数据
- **聊天记录导出/导入**：聊天记录可导出为 zip 包（含文本、图片、文件），支持导入恢复
- **朋友圈数据包**：朋友圈内容可导出/导入，支持批量勾选
- **记忆点随角色包**：记忆点自动写入角色包，导入时自动恢复
- **存储空间管理**：查看并清理应用占用的存储空间

## 如何添加角色（以 CharactersImport 为例）

角色包是一个 `.zip` 文件，App 内通过 **【我】→ 导入角色包** 导入。一个 zip 中可以包含多个角色，每个角色是一个独立的文件夹。

项目根目录的 `CharactersImport\Sample1` 就是一份可直接打包成 zip 的示例：

```
CharactersImport/
└── Sample1/
    └── 爱弥斯/                  # 角色文件夹（文件夹名即角色名，可任意命名）
        ├── Profile.json         # 角色资料（必填）
        ├── Prompt.txt           # 角色提示词 / 人设（强烈建议提供）
        ├── ProfilePicture.jpg   # 角色头像（可选）
        ├── ProfileBackground.jpg# 角色详情页背景图（可选）
        └── moments/             # 朋友圈内容（可选，结构见「moments 文件夹说明」）
            ├── moments.json     # 朋友圈记录
            └── files/           # 朋友圈图片
                ├── 01.jpg
                └── ...
```

### 步骤

1. 在 `Sample1` 下新建一个文件夹，文件夹名即角色显示名（如 `爱弥斯`）；
2. 在文件夹内新建 `Profile.json`，填入角色资料；
3. （可选）新建 `Prompt.txt` 写入角色人设提示词；
4. （可选）放入头像图片 `ProfilePicture.jpg`（支持 jpg / jpeg / png / webp / gif / bmp，缺省时取角色目录内第一个图片文件）；
5. （可选）放入背景图 `ProfileBackground.jpg`（角色详情页封面背景图，缺省时详情页显示默认渐变）；
6. （可选）新建 `moments` 文件夹写入角色的朋友圈内容（格式见「moments 文件夹说明」）；
7. 将整个 `Sample1` 文件夹压缩为 zip；
8. 在 App 中进入 **【我】→ 导入角色包**，选择该 zip 并勾选要导入的角色。

### Profile.json 字段说明

| 字段 | 说明 | 是否必填 |
| ---- | ---- | ---- |
| `name` | 角色名称（缺省时使用文件夹名） | 建议 |
| `location` | 所在地（映射到「地区」） | 可选 |
| `gender` | 性别 | 可选 |
| `signature` | 个性签名 | 可选 |
| `remark` | 备注 | 可选 |
| `description` | 角色简介 | 可选 |
| `personality` | 性格特征 | 可选 |
| `greeting` | 开场白 | 可选 |
| `user_relationship` | 与用户的关系 | 可选 |
| `active_start` / `active_end` | 活跃时段，值为 `"HH:mm"`（如 `"09:00"`）；两者同时设置并生效后，在该时间段内聊天角色不会主动道别、说晚安，保持活跃；任一为空表示未设置 | 可选 |
| `tags` | 标签数组，如 `["鸣潮","电子幽灵"]` | 可选 |
| `avatar` | 内嵌头像（base64 字符串，存在时优先于图片文件） | 可选 |
| `background` | 内嵌背景图（base64 字符串，存在时优先于 `ProfileBackground.jpg`） | 可选 |
| `memory_points` | 持久化记忆数组（可选），元素为 `{"content": "记忆内容", "created_at": "创建时间"}`；导入角色包时写入该角色的记忆库 | 可选 |

`Sample1\爱弥斯\Profile.json` 示例：

```json
{
    "name": "爱弥斯",
    "location": "拉海洛·星炬学院",
    "gender": "女",
    "signature": "关注飞行雪绒喵~",
    "active_start": "00:00",
    "active_end": "23:59"
}
```

> **活跃时段设置示例**
> - **全时段活跃**：如上例，`active_start` 填 `"00:00"`、`active_end` 填 `"23:59"`，角色全天保持活跃，任何时间聊天都不会主动道别 / 说晚安；
> - **指定时段活跃**：如 `"09:00"` ~ `"23:00"`，仅在该时间段内保持活跃，时段外（如深夜）仍按角色人设作息判断是否道别；
> - 该字段不填（或任一项为空）即表示未设置活跃时段，保持原「按人设作息」逻辑。

### Prompt.txt 说明

`Prompt.txt` 的内容就是角色的 `systemPrompt`，App 在每次对话前会把它与用户资料、时间、输出格式指令一起组装成 System Prompt。

参考 `Sample1\爱弥斯\Prompt.txt`：建议写清楚角色**基础身份**、**性格特征**、**说话风格**、**核心记忆与执念**、**注意事项**，让角色行为稳定、性格鲜明。

### moments 文件夹说明（朋友圈）

角色包中可选的 `moments` 文件夹用于承载角色的**朋友圈内容**，结构与聊天记录导出包类似：`moments.json` 记录动态（文案 / 点赞 / 评论），`files/` 目录存放动态引用的图片。

```
moments/
├── moments.json   # 朋友圈记录（必填）
└── files/         # 朋友圈图片（由 images 相对路径引用）
    ├── 01.jpg
    └── ...
```

`moments.json` 根对象包含 `character_name`（角色名）与 `moments` 数组，数组内按时间倒序（新在前）排列各条动态：

| 字段 | 说明 |
| ---- | ---- |
| `character_name` | 角色名（根对象） |
| `moments` | 动态数组（根对象） |
| `id` | 动态唯一标识（可选，缺省自动生成） |
| `content` | 朋友圈正文文案 |
| `images` | 图片相对路径数组，如 `["files/01.jpg"]`，对应 `files/` 目录下的图片文件（可选） |
| `likes` | 点赞昵称数组，如 `["千咲","琳奈"]`（可选） |
| `comments` | 评论数组，每条为 `{"sender":"昵称","content":"评论内容"}`；需要表达「回复某人」时可增加 `"reply_to":"被回复昵称"`（可选，详见下方「带回复评论」） |
| `created_at` | 发布时间（ISO 8601 字符串，可选） |

`Sample1\爱弥斯\moments\moments.json` 示例：

```json
{
    "character_name": "爱弥斯",
    "moments": [
        {
            "id": "m1",
            "content": "这小手机怎么这么好玩~睡觉耽误玩手机，玩手机耽误睡觉。",
            "images": ["files/01.jpg"],
            "likes": ["千咲", "琳奈", "漂泊者"],
            "comments": [
                { "sender": "爱弥斯她老冯", "content": "不许玩了，快睡觉" },
                { "sender": "琳奈", "content": "姐们你太坑了" }
            ],
            "created_at": "2026-08-11T23:00:00.000"
        },
        {
            "id": "m2",
            "content": "老爹老妈的合影~还有老妈和我的合影~",
            "images": ["files/02.jpg", "files/03.jpg"],
            "likes": ["漂泊者", "千咲", "莫宁", "琳奈", "西格莉卡"],
            "comments": [
                { "sender": "莫宁", "content": "漂泊者这身很漂亮" }
            ],
            "created_at": "2026-08-05T22:30:00.000"
        }
    ]
}
```

#### 带回复评论（`reply_to`）

普通评论只需 `sender` + `content`；若要表达「某人回复了某人」，在评论对象里额外加一个 `reply_to` 字段，值为被回复者的昵称。App 内展示为 **「发送者 回复了 被回复者：评论内容」**。

```json
{
    "sender": "爱弥斯",
    "content": "不许玩了，快睡觉",
    "reply_to": "漂泊者"
}
```

- `reply_to` 为**可选**字段，缺省（或空字符串）时按普通评论展示「发送者：内容」；
- 旧版只有 `sender` + `content` 的评论 JSON 保持不变，与带回复评论互相兼容；
- 用户在朋友圈内**点击某条评论**即可套用「回复该昵称」的输入框，发送后生成带 `reply_to` 的评论；用户评论角色的朋友圈后，角色会以带 `reply_to` 的评论进行回复，回复者按以下规则确定：
  - 被回复的昵称**存在于通讯录**（且非"自己"）→ 以该角色身份回复；
  - 被回复的昵称不在通讯录 → 由该条动态的**发布者角色**回复；
  - 回复目标为"自己" → 不触发 AI 回复。
- 角色回复优先使用「朋友圈互动」模型（未配置时回退聊天模型）；若上下文估算已达到互动模型上下文窗口的 **70%**，会自动将最近聊天记录压缩为摘要后再请求模型。相关调试日志输出到 App 内「开发者日志」栏目。

- 图片文件支持 jpg / jpeg / png / webp / gif / bmp，放在 `files/` 目录下，由 `images` 字段以 `files/xxx.jpg` 的相对路径引用；单条动态最多展示 **9 张**（超出部分截断），1 张为大图、多张按 3 列网格排列（对齐微信朋友圈）；
- 没有 `moments` 文件夹时角色无朋友圈内容，详情页朋友圈区域显示空态；
- 文本文件建议使用 UTF-8 编码（与角色包其他文件一致）。

### 注意事项

- 文本文件建议使用 **UTF-8** 编码；程序对 GBK 乱码有兼容处理，但建议统一 UTF-8；
- zip 中**必须**包含至少一个带 `Profile.json` 的角色文件夹，否则会被过滤；
- 文件层级不要过深：`Sample1\角色A\Profile.json` 即可，不要把文件直接放在 zip 根目录。

## 朋友圈数据包（导入 / 导出）

App 内通过 **【我】→ 管理当前朋友圈** 管理朋友圈数据：顶部「导入朋友圈数据包」从 zip 导入；下方列表展示**已有朋友圈数据的角色**（可勾选）；底部「导出选中」把所选角色的全部朋友圈打包为 zip。**导入与导出的数据包结构一致，可互相回环**。

### 数据包结构

与角色包内 `moments/` 文件夹的内容格式相同：每个角色一个文件夹，`moments.json`（朋友圈记录）与图片文件夹（`files/`，由 `images` 相对路径引用）**直接放在角色文件夹下**（不含 `moments/` 外层包裹）。数据包**必须**以角色文件夹为单位，支持以下两种布局：

**布局一：带总包名（导出使用此结构）**

```
朋友圈_20260812_153000.zip
└── Moments/                    # 总包名（顶层文件夹，可任意命名）
    ├── 爱弥斯/                 # 角色文件夹（文件夹名即角色名）
    │   ├── moments.json        # 朋友圈记录
    │   └── files/              # 朋友圈图片
    │       ├── 01.jpg
    │       └── ...
    └── 其他角色/
```

**布局二：不带总包名（兼容导入）**

```
爱弥斯/
├── moments.json
└── files/
    ├── 01.jpg
    └── ...
```

两种布局均可导入；多个角色放同一个 zip 时建议统一使用同一布局。`moments.json` 的字段格式与上文「moments 文件夹说明」一致（`character_name` + `moments` 数组）。

### 导入规则

- 按**角色名**（备注/昵称）匹配已有角色：匹配到则**更新**该角色的朋友圈（整体替换）；未匹配到则新建一个角色（仅名称 + 朋友圈，可在「管理当前角色」中补充头像等资料）；
- 图片从数据包 `files/` 目录提取到应用本地，`images` 字段自动改写为本地路径；
- zip 中找不到任何 `moments.json` 时提示导入失败。

### 导出规则

- 在「管理当前朋友圈」勾选角色后点击「导出选中」，生成 `朋友圈_yyyyMMdd_HHmmss.zip`（保存到下载目录）；
- 导出结构为**布局一**（总包名 `Moments` + 角色文件夹），`moments.json` 与 `files/` 直接位于角色文件夹下，图片写入 `files/` 并以 `files/xxx.jpg` 相对路径引用，可直接再次导入；
- 仅导出有朋友圈数据的角色；单个角色的导出内容即其全部朋友圈动态。

## 持久化记忆（保存与导入 / 导出）

持久化记忆（记忆点）是用户主动保存的、需要模型在后续对话中长期记住的关键信息：在聊天中**长按消息 → 多选 → 保存为记忆点**，或在会话详情「提示词设置 → 记忆点管理」中手动添加 / 编辑 / 删除。记忆点会随角色的**系统提示词**一起发送给模型，聊天与朋友圈互动（自动发帖 / 点赞评论 / 回复评论）均生效。

### 保存格式（App 内）

每个角色独立一组记忆点，持久化在 SharedPreferences，键为 `memory_points_v1_<角色id>`，值为按创建时间**倒序（最新在前）**排列的 JSON 数组：

```json
[
  {
    "id": "f3a9c2e0-0000-0000-0000-000000000001",
    "content": "用户喜欢深夜聊天，不喜欢被催促睡觉",
    "created_at": "2026-08-01T21:30:00.000"
  }
]
```

| 字段 | 说明 |
| ---- | ---- |
| `id` | 记忆点唯一标识（角色包中不包含，导入时会重新生成） |
| `content` | 记忆内容 |
| `created_at` | 创建时间（ISO 8601 字符串） |

持久化记忆随**角色包**一起导入 / 导出：导出角色包时，记忆点自动写入 `Profile.json` 的 `memory_points` 字段；导入角色包时自动恢复到对应角色，无需额外操作。

### 角色包中的格式（Profile.json）

角色包内每个角色的 `Profile.json` 新增可选字段 `memory_points`，数组元素为 `{"content": "...", "created_at": "..."}`：`content` 为记忆文本，`created_at` 为 ISO 8601 创建时间（可省略，缺省按导入时间）。导出角色包时自动写入，角色没有记忆点时不生成该字段。

`Sample1\爱弥斯\Profile.json` 示例：

```json
{
    "name": "爱弥斯",
    "location": "拉海洛·星炬学院",
    "signature": "关注飞行雪绒喵~",
    "memory_points": [
        {
            "content": "用户喜欢深夜聊天，不喜欢被催促睡觉",
            "created_at": "2026-08-01T21:30:00.000"
        },
        {
            "content": "约好周末一起看新出的电影"
        }
    ]
}
```

### 导入规则

导入角色包（【我】→ 管理当前角色 → 导入角色包，或创意工坊的「角色」分类 zip）时，记忆点随角色一起恢复：

- **新角色**：包内记忆点直接写入该角色（保留原创建时间）；
- **同名角色**（覆盖导入）：包内记忆点**整体替换**该角色已有的记忆（与资料、提示词、朋友圈的处理一致，聊天记录不受影响）；
- 角色包无 `memory_points` 字段或数组为空：不改变该角色已有的记忆；
- 记忆点内容相同的自动去重。

## 群聊功能

### 创建群聊

在通讯录页面点击右上角「+」→「创建群聊」，选择多个角色加入群聊。群聊支持：

- **群名称**：自定义群聊名称
- **群头像**：支持自定义群头像，未设置时自动生成成员拼图头像
- **群简介**：设置群聊简介，角色会按简介语境进行对话
- **群成员**：选择多个角色加入群聊

### 群聊设置

进入群聊后，点击右上角「...」→「群聊设置」可配置：

- **上下文条数**：群聊可独立设置上下文条数，或跟随全局设置
- **不说话概率**（0~1，默认 0.2）：每轮每个未被 @ 的角色以此概率保持沉默，被 @ 的角色必定发言
- **引用回复概率**（0~1，默认 0.2）：角色发言时以此概率引用最近其他成员的消息

### 群聊交互

- **@ 角色**：在输入框中输入 `@角色名` 可 @ 特定角色，被 @ 的角色必定发言
- **引用回复**：长按消息可引用回复，角色发言时可引用其他成员的消息
- **未读消息**：群聊支持未读消息计数，离开群聊页面时累计新消息

### 群成员管理

- **群成员记忆**：可为每个群成员单独管理记忆点
- **群成员模型**：可为每个群成员单独配置使用的模型

## 自动发朋友圈与主动问候

### 自动发朋友圈

角色可按设定的周期自动生成并发布朋友圈内容。

**配置入口**：角色详情页 → 自动发朋友圈

- **启用**：开启后角色会按周期自动发布朋友圈
- **发布周期**（小时）：每隔多少小时发布一条，默认 72 小时（3 天）
- **周期内发布条数**：每个周期内发布的朋友圈条数，默认 1 条
- **可见范围**：设置自动发布的朋友圈可见范围（仅自己/全部/自定义分组）

**触发机制**：

- 应用启动 / 回到前台时检查并补发布
- 低频（一周 <7 条）补发积压的上限：最多一次补发 3 条
- 全程串行，一次只发一个 LLM 请求
- 失败静默跳过并记录日志，不弹 Toast 干扰用户

### 主动问候

角色在用户一段时间未聊天后，会主动发送问候消息。

**配置入口**：角色详情页 → 主动问候

- **启用**：开启后角色会主动发送问候消息
- **无消息触发时间**（小时）：用户多少小时未与角色聊天后触发，默认 72 小时（3 天）

**触发机制**：

- 应用启动 / 回到前台时检查是否到期
- 到期后角色会发送一条问候消息
- 消息会推送到系统通知栏

## 记忆池（跨场景记忆）

聚合角色在「当前会话之外」的近期记忆，让角色在私聊/群聊/朋友圈互动中保持跨场景的记忆连贯（类似真人好友记得你私聊说过什么、群里发过什么、朋友圈发过什么）。

### 记忆池内容

1. **近期私聊内容**：条数 = 全局上下文设置；私聊场景下已作为对话历史传入，跳过
2. **近期朋友圈**：最近 N 条贴文 + 全部点赞与评论（N = 全局「朋友圈记忆条数」，默认 3，0=不拼）
3. **近期群聊内容**：该角色参与的、最近有消息的 1 个群，每群最近 3 条文本消息；群聊场景排除当前群，避免与对话历史重复
4. **角色资料卡**：昵称/关系/备注/签名/地区/性格/介绍/开场白/标签，只拼非空字段
5. **用户资料**：昵称/性别/地区/签名，需传入 User，只拼非空字段

### 配置

**入口**：**【我】→ 设置 → 记忆池管理**

- **朋友圈记忆条数**：每个角色最近 N 条朋友圈贴文（默认 3，0=不拼入）
- **按角色停用来源**：可为每个角色独立停用记忆池的各个来源（近期私聊/近期朋友圈/近期群聊/角色资料卡）

## 修改应用版本号（V1.0.0）

> 约定：版本号完全由**开发者自行设置**，没有固定递增规则。在 `pubspec.yaml` 中自由填一个版本号即可，GitHub Release 的 `tag` 与它保持一致。

版本号定义在项目根目录的 `pubspec.yaml`：

```yaml
version: 1.0.0
```

- 开发者自由填写版本号（如 `1.0.0`、`1.1.0`），App 内「软件版本」显示为 `V1.0.0`；
- 不需要 `1.0.0+1` 这种带 build 号的写法，一个数字即可。

发布流程：

1. 开发者在 `pubspec.yaml` 中填写想要的版本号，例如 `1.0.0` → `1.1.0`；
2. 执行 `build_apk.bat` 打包（产物为 `build\app\outputs\flutter-apk\AiChat-V1.1.0.apk`）；
3. 在 Gitee 与 GitHub 仓库各新建一个 Release：`tag` 填与 pubspec 相同的版本号（如 `1.1.0`，可带可不带 `v` 前缀；必须比本地版本新，更新检测据此提示升级），并上传 **按命名标准命名** 的 APK 资产 `AiChat-V1.1.0.apk`。

> 说明：App 内「软件版本」通过 `package_info_plus` 读取，`flutter build apk` 会把 pubspec 中的版本写入 APK，无需手动改 AndroidManifest。

## 本地打包 APK

项目根目录已提供一键打包脚本 **`build_apk.bat`**（需已安装 Flutter 并配置 PATH）：

```bat
:: 打包 debug 包
build_apk.bat debug

:: 打包 release 包（默认，按 ABI 拆分）
build_apk.bat
```

脚本会自动执行 `flutter pub get` → `flutter build apk --release --split-per-abi`，并按 ABI 拆分输出 APK：

```text
build\app\outputs\flutter-apk\
├── AiChat-V1.0.0.apk                # 向后兼容版（arm64-v8a 复制）
├── AiChat-V1.0.0-arm64-v8a.apk      # ARM64 设备
├── AiChat-V1.0.0-armeabi-v7a.apk    # 32 位 ARM 设备
└── AiChat-V1.0.0-x86_64.apk         # x86_64 模拟器/设备
```

**说明**：
- `AiChat-V1.0.0.apk`（无 ABI 后缀）是 `arm64-v8a` 的复制，用于向后兼容（部分下载源要求固定文件名）
- 大多数现代 Android 手机使用 `arm64-v8a`
- 发布到 GitHub/Gitee Release 时，建议上传 `AiChat-V1.0.0.apk`（兼容版）

也可以手动执行：

```bash
flutter pub get
flutter build apk --release --split-per-abi
# 产物位于 build\app\outputs\flutter-apk\
```

## 自动更新机制

- **版本检查（双源）**：
  1. 优先 Gitee：`https://gitee.com/api/v5/repos/Murchey/AiChatApp/releases/latest`（国内直连）；
  2. 备用 GitHub：`https://api.github.com/repos/Murchey/AiChatApp/releases/latest`（可叠加加速代理）。
  对比 `tag_name` 与本地版本号，取 Gitee 优先的版本与更新说明；
- **下载源选项卡**：发现新版本弹窗内提供「下载源」选项卡，**默认首选 Gitee**、其次 GitHub；GitHub 源可叠加加速代理下载；
- **APK 资产命名标准**：`AiChat-V1.0.0.apk`（`AiChat-V<版本号>.apk`），检测时优先取符合标准的资产，无资产时按此命名拼接下载直链；
- **安装**：下载到应用外部目录 `updates/`，通过原生 FileProvider + 系统安装器安装（需授权「安装未知应用」）；
- 入口：
  - **【我】→ 软件版本**：手动检查更新；
  - **【我】→ 设置 → 启动时自动检测更新**：开启后每次启动自动检测；
  - **【我】→ 设置 → GitHub 加速地址**：选择/自定义加速代理（仅影响 GitHub 源下载）。

发布新版本流程：在 **Gitee 与 GitHub 仓库**各新建一个 Release，`tag` 填与 `pubspec.yaml` 相同的版本号（可带 `v` 前缀，需比本地版本新），并上传按命名标准命名的 APK 资产 `AiChat-V<版本号>.apk` 即可。

## API 设置与压缩会话

### API 设置（【我】→ API 设置）

- 添加模型：支持任意 OpenAI 兼容接口，填「展示名称 / 模型名称 / 接口地址 / API Key / 上下文长度(token)」；
- **厂商预设**：内置多个 AI 厂商配置预设（OpenAI、Google Gemini、小米 MiMo 等），一键填入配置
- **模型检测**：支持一键检测可用模型列表
- 为每个模型配置**上下文长度**，作为会话压缩 70% 阈值的基准；
- **压缩会话使用的模型**：单独指定用于压缩的模型（默认跟随聊天模型）；
- **朋友圈互动模型**：单独指定用于朋友圈互动（自动发帖/点赞评论）的模型。

### 会话压缩（【我】→ 聊天设置 → 压缩会话）

- 上下文条数滑到【无限制】时自动开启「自动压缩历史消息」；
- 聊天设置页顶部实时显示**当前会话的上下文使用情况**：已用 / 总 token、占用百分比、进度条与压缩阈值刻度线，达到阈值时提示"下次发送将自动压缩"；
- 压缩阈值可手动调整（30% ~ 90%，默认 70%）：当会话历史估算 token 达到所选模型上下文长度的阈值时，自动把更早的历史消息（保留最近 20 条）压缩为一段摘要，并替换进会话记录，避免上下文超长；
- 压缩请求使用「压缩会话使用的模型」完成。
