# MiMo 声音克隆、音色设计与角色包附带方案

> 更新时间：2026-09-24。资料来源为 MiMo 官方语音合成文档，仅记录已核对的接口协议与应用侧设计，不记录 API Key 等凭据。

官方文档：https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/audio/speech-synthesis-v2.5

---

## 一、MiMo 三个 TTS 模型的分工

| Model ID | 音色来源 | 不支持 |
|---|---|---|
| `mimo-v2.5-tts` | 预置音色 ID | 音色设计、音色复刻 |
| `mimo-v2.5-tts-voicedesign` | 文本描述自动生成 | 唱歌、预置音色、音色复刻 |
| `mimo-v2.5-tts-voiceclone` | 音频样本复刻 | 唱歌、预置音色、音色设计 |

三个模型共用同一入口：

- Base URL：`https://api.xiaomimimo.com/v1`
- Endpoint：`POST /chat/completions`
- Authorization：`Bearer {API Key}`
- 响应：`choices[0].message.audio.data` 为 Base64 编码音频（非流式，`format: "wav"`）

### 通用调用规则

- 待合成文本必须放在 `role: "assistant"` 的 `content` 中。
- `role: "user"` 消息可选，用于自然语言风格指令或对话历史（内容不会被读出）。
- `mimo-v2.5-tts-voicedesign` 的 `user` 消息为必填（音色设计描述）。

## 二、声音复刻（Voice Clone）调用协议

### 2.1 音频样本要求

- 仅支持 `mp3` 与 `wav` 格式。
- Base64 编码后的字符串长度不能超过 **10 MB**。
- 必须使用 Data URI 前缀：

```text
data:{MIME_TYPE};base64,$BASE64_AUDIO
```

| 原文件格式 | MIME_TYPE |
|---|---|
| mp3 | `audio/mpeg`（或 `audio/mp3`） |
| wav | `audio/wav` |

`$BASE64_AUDIO` 是音频文件的纯 Base64 编码（不含前缀）。

### 2.2 请求体结构

```json
{
  "model": "mimo-v2.5-tts-voiceclone",
  "messages": [
    { "role": "user", "content": "" },
    { "role": "assistant", "content": "要合成的目标文本" }
  ],
  "audio": {
    "format": "wav",
    "voice": "data:audio/mpeg;base64,{BASE64_SAMPLE}"
  }
}
```

说明：

- `audio.voice` 直接填入样本 Data URI，不是音色名。
- `user.content` 可为空字符串；也可填自然语言风格指令（如「语速稍慢，温柔一点」），同样不会被读出。
- 风格标签（如 `(温柔)`）仍可写进 `assistant.content`。
- `audio.format` 非流式推荐 `wav`；流式必须 `pcm16`。

### 2.3 响应结构

与预置音色一致：

```json
{
  "choices": [
    {
      "message": {
        "audio": { "data": "{BASE64_WAV}" }
      }
    }
  ]
}
```

### 2.4 应用侧建议

- 角色资料卡的 `voice_id` 字段可直接承载 Data URI，但体积大且不可读。
- 更合理的做法是把样本作为独立文件随角色包分发，应用在调用前组装 Data URI（见第四节）。
- 样本建议 10–20 秒、清晰干净的人声；过短或带 BGM 的样本会影响复刻质量。

## 三、音色设计（Voice Design）调用协议

### 3.1 请求体结构

```json
{
  "model": "mimo-v2.5-tts-voicedesign",
  "messages": [
    { "role": "user", "content": "温柔清澈的年轻女声，语速稍慢……" },
    { "role": "assistant", "content": "要合成的目标文本" }
  ],
  "audio": {
    "format": "wav",
    "optimize_text_preview": true
  }
}
```

说明：

- `user.content` 是音色设计描述，**必填**。
- 不传 `audio.voice`——音色由描述自动生成。
- `optimize_text_preview: true` 时可省略 `assistant` 消息，由模型润色生成播报文本（适合试听）。
- 流式调用暂未上线低延迟版本（目前降级为兼容模式）。

### 3.2 音色描述写法

官方建议 1–4 句，覆盖以下维度中的若干项：

| 维度 | 示例 |
|---|---|
| 性别与年龄 | 「二十多岁的年轻女性」「五十多岁的中年男性」 |
| 音色/质感 | 「丝滑醇厚、带着磁性」「清亮稚嫩」 |
| 情绪/语气 | 「温柔但带着一丝疲惫」「热情自信」 |
| 语速/节奏 | 「语速稍慢，吐字清晰」「像连珠炮」 |

避免冲突特征、后期效果词（混响/EQ）、模糊词（「好听的」「正常的」）。

## 四、角色包如何附带已克隆声音

### 4.1 当前格式（预置音色 / 风格描述）

`Profile.json` 中：

```json
{
  "voice": {
    "voice_id": "茉莉",
    "instructions": "温柔清澈的年轻女声，语速稍慢……"
  }
}
```

### 4.2 扩展格式（携带克隆样本）

角色包 ZIP 内增加音频样本文件，`Profile.json` 增加样本引用：

```text
character-pack.zip
├── Profile.json
├── Prompt.txt
├── avatar.png
└── voice/
    └── sample.mp3        ← 克隆样本（mp3 或 wav）
```

`Profile.json`：

```json
{
  "voice": {
    "type": "clone",
    "sample_file": "voice/sample.mp3",
    "mime_type": "audio/mpeg",
    "instructions": "语速稍慢，温柔、克制"
  }
}
```

字段约定：

| 字段 | 必填 | 说明 |
|---|---|---|
| `voice.type` | 是（克隆时） | 固定 `"clone"`；预置音色可省略或写 `"preset"` |
| `voice.sample_file` | 是（克隆时） | ZIP 内相对路径，建议固定 `voice/sample.{mp3\|wav}` |
| `voice.mime_type` | 是（克隆时） | `audio/mpeg` / `audio/mp3` / `audio/wav` |
| `voice.voice_id` | 预置音色时 | 预置音色 ID（如 `茉莉`） |
| `voice.instructions` | 可选 | 风格指令，作为 `user` 消息传入 |

兼容性规则：

- 旧角色包（无 `type` / `sample_file`）继续按预置音色处理。
- 缺少样本文件或样本超过 10 MB（Base64 后）时，导入给出可读错误，不静默失败。
- 导出角色包时，若角色配置了克隆样本，自动打包 `voice/` 目录。

### 4.3 应用调用流程

1. 读取角色的 `voice.type` 与 `sample_file`。
2. 读取样本文件字节，组装 Data URI：`data:{mime_type};base64,{base64}`。
3. 使用 `mimo-v2.5-tts-voiceclone` 模型发起请求。
4. 解析 `choices[0].message.audio.data`，解码后播放。

### 4.4 样本体积与打包注意

- 单个样本 Base64 后 ≤ 10 MB；原始文件建议 ≤ 7 MB。
- 角色包整体不宜过大，建议单一样本控制在 30 秒以内。
- 多角色群聊按各自角色的样本分别请求，不能混用。

## 五、【我】页声音工作台设计（规划）

入口：【我】→ 新增「声音工作台」（Cupertino 风格列表项，与「管理当前角色」同级）。

页面结构：

1. **音色设计**
   - 输入音色描述（多行）。
   - 输入/选择试听文本。
   - 「生成试听」按钮 → 调用 `mimo-v2.5-tts-voicedesign`。
   - 试听播放控件（复用播放状态图标规范）。
   - 「应用到角色…」→ 选择角色并写入 `voice.instructions`。

2. **声音克隆**
   - 「选择音频样本」→ 系统文件选择器（mp3/wav）。
   - 显示样本文件名、时长、大小；超过限制时禁用生成。
   - 输入试听文本 → 「克隆试听」→ 调用 `mimo-v2.5-tts-voiceclone`。
   - 「保存为角色声音」→ 选择角色，复制样本到角色包存储并写入 `voice` 扩展字段。

3. **已保存声音**
   - 列出角色已配置的音色（预置 / 设计 / 克隆）。
   - 支持试听、替换、删除。

UI 风格约束（与现有设置页一致）：

- `CupertinoPageScaffold` + `CupertinoNavigationBar`。
- 分组使用 `CupertinoListSection.insetGrouped`。
- 操作按钮用 `CupertinoButton` / `CupertinoButton.filled`。
- 弹层用 `showCupertinoModalPopup` 底部 Panel。
- 强调色与文字颜色走 `context.accentColor` / `context.textPrimaryColor` 等 theme 扩展。

## 六、与播放队列改造的关系

本文件描述的是音色来源（预置 / 设计 / 克隆）；播放控制（排队、停止、状态图标、多条连续播）属于独立的播放状态机改造，见 Compose 功能规格 `docs/compose/spec/tts-playback-queue.md`。两者通过统一的 `TtsService.speak` / 播放状态流对接：

- 音色组装在请求层（本文件第四节）。
- 播放排队与 UI 状态在播放控制层。
