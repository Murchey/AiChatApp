## 先明确哪些位置被替换

本包只改变底部导航图标、首页与通讯录的 Header 背景，以及我方文字消息气泡。不替换角色聊天会话的 Header，不改变角色头像、角色气泡、图片、附件或表情包。没有打包字体，保留用户原来的字体选择。

Header 只在 `headers.home`、`headers.contacts` 声明；这两个槽位共用一张图片，不存在聊天页 Header 槽位。App 保留原标题、搜索、加号和点击区域；启用对应图片时，Header 内容高度从 44 加高到 60 个逻辑像素（另加状态栏），背景图不响应点击。禁用后恢复原高度，聊天会话 Header 不变。

| `nav bar img/Home.png` | 1027×1069 | `navigation.chat` 首页 | 192×192 透明 PNG |
| `nav bar img/2.png` | 960×1152 | `navigation.contacts` 通讯录（按剩余槽位映射） | 192×192 透明 PNG |
| `nav bar img/moments.png` | 1260×1504 | `navigation.discover` 发现 | 192×192 透明 PNG |
| `nav bar img/me.png` | 948×1080 | `navigation.profile` 我 | 192×192 透明 PNG |

| 脚本绘制藏青底版 | — | 我方气泡九宫格底图 | 240×120 透明圆角 PNG |

透明素材先按 Alpha 包围盒去除无效空白，再等比缩放到方形画布，四边保留透明余量。不能直接将竖图拉成正方形，否则人物会变形。导航槽位设置 `size: 36`，App 额外放大 10%，实际显示为 39.6 个逻辑像素，让人物更清晰；导航文字变大时，App 会优先保留文字空间，按剩余高度等比缩小图标，避免底部溢出；实际像素尺寸仍填 192×192，不改点击区域、文字和选中描边。

选中态不另做素材：`normal` 与 `selected` 指向同一个文件，沿用 App 原来的选中标记。主题不要把描边烘焙进图片，以免出现双重选中效果。当前清单仍保留两项路径，兼容既有解析规范。

## Header：使用预先构图的横幅

当前使用用户重新提供的 `HeaderImg.png`，实际尺寸为 1596×471。脚本不裁剪、不缩放，保留原始构图，并将实际宽高写入首页和通讯录的清单。`NewHeaderImg.jpg` 保留为历史素材，不再参与生成，也不沿用更早竖图的裁剪坐标。

471 是资源像素高度，不是顶部栏的布局高度；App 顶部栏仍为 60 个逻辑像素，另加状态栏。App 使用 `BoxFit.cover` 等比铺满，水平居中、偏上取景（垂直对齐 -0.4），不同屏幕比例可能裁去少量边缘。不要用 `BoxFit.fill` 强制拉伸，或为了匹配资源像素而再次加高顶部栏。制作新主题时优先提供构图完成的横幅，将重要人物和装饰放在安全区域，并检查带状态栏的实际页面。

App 按深浅模式叠加背景遮罩，保留标题和操作按钮可读性。不要将标题等必要文字绘制进背景图。

实际 Flutter 绘制还发现了一个问题：Cupertino 导航栏默认会模糊背后的图像，即使背景色设成透明，人物仍然看不清。本次在有主题 Header 时关闭该栏的背景模糊，使用主题遮罩维持可读性；无主题 Header 时继续沿用原来的模糊效果。后续制作时应同时检查图片素材和 App 的模糊/遮罩，不能只检查打包预览。

Header 必须绘制在导航栏自身的背景层。放在整个 Scaffold 后面的图片，会被非空会话列表和通讯录的不透明背景盖住；只检查空列表会漏掉这个问题。回归测试使用有内容且背景不透明的列表，在深浅模式下检查实际绘制像素。仅首页和通讯录使用此包装，聊天会话标题栏不受影响。

还需要在启用 Header 时关闭 Cupertino 导航栏的 `automaticBackgroundVisibility`：否则列表位于顶部时，框架会用页面底色替代透明导航栏背景，再次遮住主题图片。未启用主题 Header 时保留系统默认行为。

## 气泡：底色、人物和正文分开

底色采用藏青 `#182B49`，默认文字为白色 `#FFFFFF`。底图尺寸 240×120，四边九宫格固定区域各 24 像素。底图只负责背景，人物不烘焙进九宫格：长消息会拉伸中心和边缘，人物会变形或被文字覆盖。

为此增加了可选的 `selfBubble.leading`：

```json
{
  "file": "images/self-bubble.png",
  "width": 240,
  "height": 120,
  "stretchInsets": {"left": 24, "top": 24, "right": 24, "bottom": 24},
  "textColor": "#FFFFFF",
  "leading": {
    "file": "images/bubble-leading.png",
    "width": 320,
    "height": 320,
    "size": 56,
    "gap": 8
  }
}
```

这段是 `selfBubble` 的值。`leading` 图片按 56×56 逻辑像素等比显示，叠在气泡最左侧边缘，40% 宽度探出底图左边界，顶部探出 8 个逻辑像素，形成类似 QQ 个性气泡的贴边装饰。正文避开人物并留出 8 的间距；外层也为探出部分预留布局空间，避免被裁切或遮住相邻消息。人物不随长消息拉伸，也不是正文前的一枚表情。这里的 320×320 是文件实际像素，56 是显示尺寸，不能混用单位。`size` 允许 16–96，`gap` 允许 0–24。导入会严格校验图片及尺寸；不声明此字段的主题保持原布局。

此扩展由新版 App 渲染，旧版 App 无法显示左侧装饰。用户可在主题我方气泡设置中关闭主题气泡或修改深浅模式文字色；禁用主题后恢复原设置。

## 以后制作主题的流程

1. 收集素材，明确每个文件对应的导航槽位、Header 或气泡装饰。先确认作用页面，避免误改聊天页 Header。
2. 查看尺寸、透明通道和主体位置。导航与装饰等比缩放留边；已构图的 Header 横幅保留原始尺寸，竖图才需要先挑选主体区域；不对所有图片使用同一种裁剪方式。
3. 选择底色和文字色，在深浅模式检查对比度。人物装饰独立于九宫格底图，给正文留出空间。
4. 按实际输出像素填写 `content.json`。同图复用路径；不必复制选中态图片，也不需要添加无用途的版本字段。
5. 生成预览，并将 `content.json` 和 `images/` 直接放在 ZIP 根目录，不多套一层主题文件夹；不放入原始素材、脚本或仓库密钥。
6. 在【我 → 应用主题 → 从本地导入 ZIP 主题】安装，手动启用。测试短消息、长消息、换行、引用、深浅模式、两种导航布局、首页及通讯录按钮；确认聊天页 Header 和角色气泡未改变。
7. 验证启用、禁用、导出再导入。云端发布使用 GitHub/Gitee `ThemeStore` Release，或对象存储来源路径下的 `Theme/` 目录；两者名称不同。

## 重新生成本包

在仓库根目录执行（Python 需已安装 Pillow）：

```powershell
python developDocs/themes/build_hsin_theme.py
```

脚本使用 Windows 微软雅黑生成中文预览，其他系统请将 `font_file` 改为本机可用的中文字体。脚本不会把预览字体打包进主题。Header 宽高直接读取新横幅，不硬编码裁剪坐标；生成时检查所有输出尺寸与清单一致。更新图片后需重新导入 ZIP，确认替换同 ID 主题；仅更新 App 不会替换设备内已安装的资源。

输出为 `developDocs/themes/Hsin_theme/` 和同级 `Hsin_theme.zip`。脚本只在此输出目录内操作，原素材保持不变。发布新主题时应使用独立输出目录并更新 ID、显示名与映射。
