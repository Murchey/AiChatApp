# 发现页与故事线社区分阶段实施计划

## 目标

将移动端原“朋友圈”入口调整为“发现”，在发现页提供两个入口：现有朋友圈和故事线社区。故事线社区支持多来源浏览与下载，并将下载的文字故事设定安装为角色的独立记忆源。

现有朋友圈、聊天、气泡主题、角色音频、本地隐私数据和底部两种导航样式保持不变。

## 阶段一：App 侧改版（2026-10-07）

### 导航与发现页

- 将底部导航第三项改名为“发现”，继续使用指南针图标。
- 新增发现页，使用两个等宽入口卡片：朋友圈、故事线社区。
- 两种底部导航（悬浮胶囊和嵌入式 Panel）都进入发现页。
- 保留朋友圈原有列表、详情、评论、点赞、通知和滚动逻辑。

### 故事线社区客户端

- 支持四种来源：自建服务器、COS/OSS、GitHub、Gitee。
- 来源和配置保存在本地，支持地址、端口、仓库、分支、目录和 `index.json` 配置。
- 自建服务器支持健康检查、故事列表、搜索、标签和下载统计展示。
- 静态来源读取统一的 `index.json` 和故事 JSON，只提供浏览和下载，不显示统计或互动入口。
- 故事详情支持版本、作者、简介、标签、章节和记忆点预览。
- 下载后的故事需要选择本地角色，再安装为独立故事记忆源。

### 记忆源

- `MemoryPoint` 增加故事来源字段并兼容旧 JSON。
- 故事记忆可按故事来源更新、卸载和单独启停。
- 记忆池增加故事线区块和已安装故事管理。
- 更新或卸载故事不得影响手动记忆、朋友圈记忆、群聊记忆和角色资料记忆。

### 阶段一验收

- Flutter 分析和测试通过。
- Android 模拟器可以切换发现页两个入口。
- 四种来源至少完成配置读取和静态故事索引浏览。
- 故事 JSON 下载、角色绑定、记忆池启停、更新和卸载正常。
- 服务器不可用、索引损坏和故事格式错误时显示可恢复提示。

## 阶段二：Spring Boot 后端

目录：`server_project/`。

- Spring Boot 3.x、Java 21、SQLite、可执行 JAR。
- Ubuntu 直接运行，Windows 使用 PowerShell 启动并支持内网穿透。
- 提供健康检查、版本公告、邀请码兑换设备令牌、故事目录、搜索、标签、详情和下载接口。
- 仅管理员通过 JSON/YAML 和脚本发布故事，不建设网页后台。
- 服务端只保存故事元数据、故事文件和被动下载次数，不保存聊天记录、API Key 或用户资料。
- 提供 Ubuntu systemd、Windows 启动脚本和部署文档。

## 阶段三：发布与兼容完善

- 完善故事包校验、版本更新提示、缓存策略和离线失败体验。
- 增加管理脚本测试、HTTP 集成测试和数据库迁移测试。
- 评估将故事索引同步到 COS/OSS、GitHub 和 Gitee 的发布辅助工具。
- 根据模拟器和少量邀请用户反馈调整发现页信息层级。

## 统一静态故事格式

静态来源约定：

```text
index.json
stories/<storyId>/<version>.json
```

`index.json` 提供故事列表元数据，故事详情 JSON 提供章节和文字记忆点。第一版不包含图片、音频、评论、点赞和评分。

## 不在当前阶段处理

- 不改变朋友圈卡片、聊天气泡和本地聊天数据结构。
- 不在今天创建或部署 Spring Boot 服务端。
