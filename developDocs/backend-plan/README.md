# AiChat 本体后端方案

## 目标

这组文档用于从零实现 AiChat 的可选后端。实现者可以不是 GPT，也不需要依赖聊天记录上下文，只要按文档中的顺序、契约和验收条件执行即可。

后端采用 **Spring Boot 3.x + Java 21 + SQLite 的模块化单体**。第一版保持 App 的本地优先特性：聊天、角色、记忆、朋友圈和 API Key 默认仍在本地工作；后端只在用户主动配置并启用时提供设备认证、数据同步、故事社区和可选的社区互动能力。

## 总体原则

1. **本地优先**：没有后端时 App 仍能聊天、管理角色、查看本地朋友圈和使用本地 API 配置。
2. **后端不保存用户 API Key**：除非未来另行设计加密密钥托管，第一版只保存模型能力和用户选择，模型密钥留在客户端。
3. **契约优先**：先固定 JSON、错误码、版本和幂等语义，再实现 Controller；不要让客户端猜服务端字段。
4. **模块可关闭**：故事、评论、同步、LLM 中继分别由配置开关控制，未启用模块返回明确的 `FEATURE_DISABLED`。
5. **供应商无关**：业务层只依赖统一的 `ModelAdapter`，不能把 `choices[0]`、OpenAI 字段或 GPT 名称写进业务代码。
6. **可恢复失败**：网络超时、令牌过期、版本冲突、模型返回坏 JSON 都必须返回可识别错误，不能让请求永久挂起。
7. **数据可迁移**：所有表结构变更使用 Flyway；SQLite 文件、备份和导出格式都要有版本号。
8. **隐私最小化**：默认不上传聊天正文、角色私密资料和 API Key；同步范围由用户逐项开启。

## 版本边界

### V1 必须完成

- `/api/health`、`/api/version`。
- 设备邀请码兑换和设备令牌刷新/撤销。
- 故事目录、详情、下载、搜索、标签和被动下载次数。
- 客户端配置的服务器地址、端口、HTTP/HTTPS、设备令牌。
- 可选的本地数据备份上传/下载协议，但默认关闭。
- 模型能力查询和统一错误格式；至少支持 OpenAI-compatible、Anthropic、Gemini、Ollama/本地 HTTP 的适配接口定义。
- 管理员通过受保护 API 发布故事草稿、校验、审核和发布。

### V1 明确不启用

- 在线投稿、公开评论、点赞、评分和用户资料社交。
- 服务端保存原始 API Key。
- 服务端托管全部聊天记录。
- 用 SQLite 做多节点高并发写入集群。
- 让服务端执行任意用户提供的 URL、脚本或插件。

### V2 预留但不阻塞 V1

- 故事评论、回复、举报、审核状态。
- 管理员在 App 内创建和发布故事。
- 多用户同步和设备间冲突合并。
- 对话任务队列、模型路由、成本限额和审计报表。

## 完成定义

一个实现切片只有同时满足以下条件才算完成：

- 契约文档中的请求和响应字段有自动化测试。
- 网络失败、超时、重复请求、令牌失效和权限不足有测试。
- 数据库迁移可以在空库和上一版本库上运行。
- App 未配置后端时回归测试仍通过。
- 日志不打印 API Key、设备令牌、聊天正文和完整 Authorization header。
- Ubuntu 与 Windows 各有一条可复制的启动命令。
