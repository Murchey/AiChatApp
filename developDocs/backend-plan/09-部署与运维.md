# 09 部署与运维

面向部署者的逐步操作手册见 [`server_project/docs/部署指南.md`](../../server_project/docs/部署指南.md)。本文件保留架构、备份和运维约束；具体命令以该手册和仓库内模板为准。

2026-10-09 已在 Ubuntu 云服务器完成实测部署，记录见 [`09-部署实测记录-2026-10-09`](09-部署实测记录-2026-10-09.md)。

## 1. Ubuntu

准备 Java 21 和数据目录：

```bash
sudo apt update
sudo apt install -y openjdk-21-jre-headless
sudo mkdir -p /opt/aichat/data /etc/aichat
sudo useradd --system --home /opt/aichat --shell /usr/sbin/nologin aichat || true
sudo chown -R aichat:aichat /opt/aichat
```

构建与启动：

```bash
./gradlew bootJar
aichat-data-dir=/opt/aichat/data
AICHAT_DATA_DIR=$aichat-data-dir AICHAT_TOKEN_PEPPER='change-me' \
  java -jar build/libs/aichat-backend.jar
```

生产环境使用环境文件，不把 pepper 写入 shell history：

```ini
# /etc/aichat/aichat.env
AICHAT_DATA_DIR=/opt/aichat/data
AICHAT_PORT=8080
AICHAT_TOKEN_PEPPER=replace-with-random-32-bytes
AICHAT_INVITE_REQUIRED=true
```

systemd 只负责启动 JAR，服务日志进入 journald；数据库、故事文件和备份放在 JAR 外部。可直接使用 `server_project/deploy/aichat.service`，并将 `server_project/deploy/Caddyfile.example` 或 `nginx.conf.example` 按域名和证书修改后启用。

## 2. Windows

要求 Java 21，PowerShell 启动：

```powershell
$env:AICHAT_DATA_DIR = 'D:\AiChatData'
$env:AICHAT_PORT = '8080'
$env:AICHAT_TOKEN_PEPPER = 'replace-with-random-32-bytes'
java -jar .\build\libs\aichat-backend.jar
```

防火墙只开放必要端口。使用内网穿透时，隧道服务映射到本机端口，App 配置使用隧道提供的 HTTPS 地址；不要把 SQLite 文件目录暴露成共享文件夹。

## 3. HTTPS 与反向代理

推荐 Caddy/Nginx 终止 TLS，Spring Boot 只监听本机或私网端口。代理必须：

- 转发 `Authorization`、`Content-Type`、`Accept`、`X-Request-Id`。
- 配置 SSE 长连接不缓冲，并设置合理的 read timeout。
- 限制上传 body 大小和请求速率。
- 只信任代理写入的 `X-Forwarded-*`。
- 健康检查使用 `/api/health`，不把 Actuator 全部暴露公网。

## 4. 备份和恢复

每日备份至少包含：

- SQLite 数据库文件。
- `data/stories` 中的已发布故事文件。
- `application` 配置模板（不含真实 pepper）。

备份流程：暂停写入或使用 SQLite backup API → 复制到临时文件 → `PRAGMA integrity_check` → 计算 SHA-256 → 原子改名。恢复先复制到新目录并运行全部迁移，不直接覆盖正在运行的数据库。

## 5. 日志和监控

结构化日志字段：`timestamp`、`level`、`requestId`、`route`、`status`、`durationMs`、`deviceIdHash`、`errorCode`。禁止记录 token、API Key、聊天正文和完整评论。

最小监控：

- health 状态。
- 5xx 比例、P95 延迟、429 数量。
- SQLite 文件大小、磁盘剩余空间。
- 故事发布失败和下载失败。
- LLM provider 错误分类与取消数（不记录 prompt）。

## 6. 升级和回滚

1. 备份数据库和故事目录。
2. 停止旧 JAR，替换新 JAR。
3. 启动并等待 Flyway 完成。
4. 调用 `/api/health` 和一个只读故事接口。
5. 观察错误率后再恢复外部流量。
6. 迁移失败不能自动删除数据；恢复备份或执行专门的回滚步骤。

SQLite 单节点是 V1 的约束。需要多节点、全文搜索或大量评论时，先完成数据访问层抽象，再迁移 PostgreSQL，不要同时重写 Controller 和客户端协议。
