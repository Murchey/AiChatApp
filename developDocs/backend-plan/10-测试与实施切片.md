# 10 测试与实施切片

## 1. 从 0 开始的切片

### M0：工程可启动

- 创建 Spring Boot 工程、Gradle Wrapper、配置样例。
- `/api/health`、`/api/version` 和统一错误格式。
- 空库启动、Flyway 执行、JAR 打包。

验收：Ubuntu 和 Windows 各能启动；`curl /api/health` 返回 200。

### M1：设备认证

- 邀请码生成、兑换、令牌哈希、刷新和撤销。
- requestId、审计日志、限流。

验收：重复兑换、过期邀请码、撤销设备和错误 token 都有测试。

实施状态：已完成，详见 [M1-设备认证实施进度](M1-设备认证实施进度.md)。

### M2：故事只读服务

- 导入/校验静态 JSON。
- `/api/stories` 分页、搜索、标签。
- `/api/stories/{id}/download`、下载幂等统计。

验收：响应可直接被现有 `StoryProvider` 解析；静态和服务端故事详情相同。

实施状态：已完成，详见 [M2-故事只读服务实施进度](M2-故事只读服务实施进度.md)。

### M3：Flutter 服务器来源

- BackendProvider、StoryBackendService、服务器设置和错误映射。
- 未配置/超时/旧服务时回退本地或静态来源。

验收：服务器不可用不会阻塞首页、聊天和设置；刷新不会重复请求。

### M4：管理员故事发布

- 草稿、校验、审核、发布、归档、审计。
- App 编辑器只依赖 API 契约，不直接操作数据库。

验收：重复发布幂等，版本冲突可恢复，坏 JSON 错误定位到字段路径。

### M5：可选同步

- 加密 manifest、outbox、冲突检测和域开关。
- 先只同步一个非敏感域做试点，再扩展聊天/角色。

验收：断网写入不丢数据；重复上传不生成重复对象；服务端看不到明文。

### M6：LLM 适配/中继（可选）

- ModelAdapter、能力目录、至少两个不同协议适配器。
- SSE 事件、取消、usage、错误归一化。

验收：OpenAI-compatible 与 Anthropic/Gemini/Ollama 至少各有一条集成测试；不支持能力时不发送错误字段。

### M7：评论（可选）

- 只读 → 创建审核 → 回复/举报。
- feature flag 默认关闭。

验收：评论失败不影响故事详情；软删除和审核状态可恢复。

## 2. 必须自动化的测试

### 单元测试

- DTO 校验、story JSON 校验、标签规范化。
- 令牌哈希/撤销、邀请码次数并发。
- 游标编码/解码、幂等键。
- 各 ModelAdapter 的请求体和响应体映射。
- LLM 流事件转换、工具参数 JSON Schema 校验。

### Repository/迁移测试

- 空库执行全部 Flyway。
- 上一版本数据库升级后行数和索引正确。
- SQLite 并发下载统计不会丢增量。
- 软删除、版本唯一约束和评论父子约束。

### HTTP 集成测试

- MockMvc 验证状态码、错误 code、requestId、分页和 feature flag。
- 真实临时 SQLite 验证发布事务：校验失败不能留下半成品。
- 模拟超时、429、坏 JSON、SSE 中途断开和客户端取消。

### Flutter 回归测试

- 未配置后端时现有本地功能通过。
- 配置服务器、刷新 token、故事列表和详情。
- 静态来源仍兼容；服务器源不显示静态模式的限制文案。
- 超时后可以重试，列表不被错误清空。
- 管理员入口按 feature/role 显示，服务端拒绝时仍安全。

## 3. 手工验收矩阵

| 场景 | 结果 |
|---|---|
| Ubuntu 直连 | HTTPS、健康检查、故事加载 |
| Windows 本地 | PowerShell 启动、数据目录、重启持久化 |

## 4. 给任意代码模型的执行提示

开始实现前，把本目录和 `README.md` 的相关现有代码读完；先列出将新增/修改的文件，再逐切片实现。每个切片完成后运行对应单元和集成测试，不要一次重写全部 Provider。

容易做错的地方：

- 不要把模型名当能力；用 capability registry。
- 不要把 API Key、token、聊天正文打进日志。
- 不要用客户端传来的角色字段做权限判断。
- 不要把 HTTP 404 当成模块关闭。
- 不要在同步前删除本地数据；先写 outbox，再确认服务端接收。
- 不要让流式请求无限等待；必须有超时、取消和最终 done/error。
- 不要修改已执行的 Flyway 文件。
- 不要用 SQLite 自增 ID 做跨设备对象 ID。
- 不要在 V1 同时引入图片上传、评论和 LLM 中继；先完成只读故事和设备认证。
