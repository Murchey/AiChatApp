# 02 边界与部署模式

## 1. 目标架构

```text
Flutter App
  ├─ 本地 SQLite/SharedPreferences：聊天、角色、记忆、设置、API Key
  ├─ Local Providers：ChatProvider、CharacterProvider、MemoryPointProvider...
  └─ Optional BackendClient
       ├─ DeviceAuthClient
       ├─ StoryClient
       ├─ SyncClient（用户主动开启）
       ├─ CommentClient（功能开关）
       └─ AdminClient（管理员角色）

Spring Boot Modular Monolith
  ├─ Auth：设备、令牌、权限
  ├─ Story：故事目录、版本、发布、下载统计
  ├─ Sync：加密备份或增量同步
  ├─ LLM：模型能力和可选中继
  ├─ Comment：评论、回复、举报、审核
  └─ Admin：邀请码、审核、发布、审计
```

后端不是 App 的必需依赖。`BackendClient` 初始化失败时，App 应回到现有本地逻辑，不能因为云端不可达而阻塞聊天或打开设置页。

## 2. 数据边界

| 数据 | 默认位置 | V1 是否上传 | 规则 |
|---|---|---:|---|
| API Key、语音密钥 | App 本地安全存储 | 否 | 永不写入普通日志或同步包 |
| 私聊/群聊正文 | App 本地 | 否 | 用户明确开启端到端加密备份后才可上传 |
| 角色与气泡设置 | App 本地 | 否 | 继续兼容现有角色包和本地 JSON |
| 朋友圈内容 | App 本地 | 否 | 社区故事与朋友圈分开 |
| 故事元数据/正文 | 后端或静态源 | 是 | 只允许已发布版本被公开读取 |
| 下载次数 | 后端 | 可选 | 只记录聚合次数，不记录聊天内容 |
| 评论 | 后端 | V2 | 受审核状态和删除标记约束 |
| 设备公钥/令牌哈希 | 后端 | 是 | 只保存哈希和撤销状态 |

“同步”不等于“把 SharedPreferences 全部上传”。每一类数据必须有显式的 `syncScope`，默认空集。

## 3. 部署模式

### 模式 A：本地单机

- App 不配置后端。
- 故事使用 GitHub/Gitee/COS/OSS 静态源。
- 适合默认安装和离线使用。

### 模式 B：个人服务器

- Ubuntu、Windows 或内网穿透地址运行一个 Spring Boot JAR。
- 开启故事目录、邀请码和下载统计。
- 用户在 App 中填写 `https://host:port` 和设备令牌。

### 模式 C：家庭/团队私有服务器

- 开启设备白名单、管理员发布和可选同步。
- 通过 Caddy/Nginx 提供 HTTPS；不要直接暴露 SQLite 管理端口。
- 评论默认关闭，开启前需要配置审核策略和备份。

### 模式 D：未来公共社区

- 需要反向代理、持久化备份、对象存储、限流、审计和独立数据库评估。
- SQLite 只适合单节点低到中等写入量；达到多节点或高并发前必须迁移 PostgreSQL。

## 4. 模块开关规则

服务端返回 `/api/version` 中的 feature flags，客户端只把服务端明确启用的入口显示为可用。关闭模块时：

```json
{
  "error": {
    "code": "FEATURE_DISABLED",
    "message": "comments is disabled on this server",
    "requestId": "req_..."
  }
}
```

不要通过“接口 404”推断模块关闭；404 留给资源不存在，功能关闭使用 403 或明确错误码。

## 5. 与现有 App 的接入边界

- `StoryProvider` 继续支持静态来源；新增服务器来源只实现 `StoryClient` 适配，不把静态 JSON 改成服务器专属格式。
- `ApiProvider` 保持模型和 API Key 本地持久化；后端只可返回模型能力目录或可选中继配置。
- `ChatProvider`、`GroupChatProvider`、`MemoryPointProvider` 先不改数据来源；同步功能通过独立 `SyncProvider` 加入，失败不能影响已有 Provider。
- `SettingsProvider` 只增加服务器地址、设备状态和模块开关，不把令牌放入普通设置导出。
- 所有网络请求共用超时、取消、重试和错误映射，不能在每个页面里单独实现。
