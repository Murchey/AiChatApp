# M4–M7 接口补充（实施中的精确请求结构）

本文件补充 05 的字段结构；尚未完成验收的模块参见实施进度。基础 JSON envelope、requestId、管理员鉴权与设备令牌保持原约定。

## 管理故事

管理员可用 `X-Admin-Token` 引导令牌，或 `Authorization: Bearer` 管理员设备令牌。创建管理员邀请码时，管理员请求 `POST /api/admin/invites`：

```json
{"maxUses":1,"expiresInHours":24,"role":"ADMIN"}
```

普通邀请码默认 USER，客户端兑换不能自行提交角色。已绑定设备 ID 不能被另一次兑换接管；已有会话使用 refresh，重新绑定使用新的设备 ID。

```text
POST /api/admin/stories                 {document:<story JSON>,baseVersion:0}
GET /api/admin/stories/{id}/draft
PUT /api/admin/stories/{id}/draft        {document:<story JSON>,revision:1}
POST /api/admin/stories/{id}/validate    {revision:2}
POST /api/admin/stories/{id}/submit      {revision:2}
POST /api/admin/stories/{id}/publish     {revision:3,baseVersion:0}
POST /api/admin/stories/{id}/archive     {revision:4}
GET /api/admin/stories?cursor=&limit=20
GET /api/admin/audit-logs?cursor=&limit=20
```

发布必须带 `Idempotency-Key`；响应重复请求不会再产生版本。修改、提交、发布、归档递增 revision；校验记录 validatedRevision，但不修改正文修订。草稿保存允许不完整正文，validate/submit/publish 才进行完整字段校验。发布要求文档 version=baseVersion+1。已发布草稿再次编辑自动基于当前发布版本；公开详情在新版本完成发布前保持旧内容。

V2 直接导入路径 `POST /api/admin/stories/publish` 为已有管理员脚本保留；App 新编辑器使用上述修订流程。

## 可选加密同步

服务器 `AICHAT_FEATURE_SYNC=true` 仅开启模块，不自动开启任何数据域。设备还需要显式请求：

```text
PUT /api/sync/scopes/settings  {enabled:true}
GET /api/sync/manifest
PUT /api/sync/objects/settings
GET /api/sync/objects/settings
POST /api/sync/resolve
```

对象上传请求（带 Idempotency-Key）：

```json
{
  "baseRevision":0,
  "sha256":"<SHA-256 of ciphertext bytes including GCM tag>",
  "ciphertext":"<Base64 AES-GCM ciphertext + 16-byte authentication tag>",
  "nonce":"<Base64 12-byte nonce>",
  "algorithm":"AES-256-GCM"
}
```

冲突解决使用 `{domain:"settings",object:<same upload request>}`，同样检查 baseRevision。服务端不负责解密或合并内容。

域白名单：settings、characters、conversations、messages、memories。默认存储由设备 ID 隔离；启用共享空间后通过 `X-Sync-Space` 选择已加入的服务端空间，服务端验证成员权限后使用空间级 revision。密钥仍只在客户端，不能上传；API Key 不能作为同步域。

共享空间：`POST /api/sync/spaces` 创建空间并一次性返回初始加入码；`POST /api/sync/spaces/{spaceId}/invites` 由 OWNER 生成单次加入码；`POST /api/sync/spaces/join {code}` 加入；`GET /api/sync/spaces` 查看当前设备已加入空间。空间接口和带 `X-Sync-Space` 的同步接口都要求设备令牌。加入码只存哈希，默认24小时/单次有效；空间成员只能读写加密对象，不能读明文或删除其他成员数据。未带 header 的旧请求保持设备私有行为。

## 模型目录与中继

模型只通过部署者配置目录添加，参见 `server_project/config/llm.example.yml`，不接受客户端传任意 endpoint。GET `/api/models` 仅返回非敏感能力与展示名，不返回 endpoint 或密钥。

开启 `AICHAT_FEATURE_LLM_RELAY=true` 后，设备调用：

```text
POST /api/llm/completions
Authorization: Bearer <device token>
X-Provider-Key: <ephemeral provider credential>
```

请求采用 06 的统一 model/messages parts/temperature/maxOutputTokens/stream/tools/responseFormat。model 对应目录 id，不直接使用供应商名称。公网必须 HTTPS；allow-local-http 只允许本机开发夹具。

stream=true 返回 start、delta、usage（存在时）、tool_call_* 和 done/error SSE；每个请求仅一个终止事件，10秒 heartbeat，默认45秒总期限，可配置1–120秒。客户端断开会关闭供应商 response body 并取消正在等待的请求。中继单节点全局最多16个请求，设备每分钟最多30次。JSON Schema、工具参数、响应体限制和控制器生命周期已在服务端测试覆盖；公网供应商仍需部署者验收。

## 评论

`AICHAT_FEATURE_COMMENTS=false` 是默认值。开启后仅允许已发布故事，写操作要求设备身份：

```text
GET /api/stories/{id}/comments?cursor=&limit=20
POST /api/stories/{id}/comments      {body:"纯文本"}
POST /api/comments/{id}/replies      {body:"纯文本"}
DELETE /api/comments/{id}
POST /api/comments/{id}/reports      {reasonCode:"SPAM"}
GET /api/admin/comments?status=PENDING&cursor=&limit=20
GET /api/admin/comments/{id}/reports
POST /api/admin/comments/{id}/moderate {status:"VISIBLE"}
```

创建、回复、举报要求 Idempotency-Key。正文最多2000个 Unicode code points，拒绝 HTML 标签。创建后为 PENDING，管理员改为 VISIBLE 后公开；HIDDEN 隐藏，DELETED 展示占位，VISIBLE 恢复。回复只有二级，一级隐藏时对应回复不公开。

举报 reasonCode 支持 SPAM、ABUSE、ILLEGAL、OTHER；同设备同评论未处理举报去重；审核时标记举报已处理。删除仅作者或管理员可用；管理员审核/删除写审计摘要，不写评论正文。普通评论每设备每故事每分钟10次，举报每设备每分钟10次。
