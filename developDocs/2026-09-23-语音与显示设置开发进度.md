### 2. TTS 当前协议支持范围已收窄

由于不同平台 TTS 协议不统一，当前代码和设置页已经明确区分：

| 类型 | 当前状态 | 当前实现 |
|---|---|---|
| Qwen DashScope 原生 TTS | 已接入代码 | DashScope 原生多模态生成接口 |
| OpenAI 兼容 TTS | 已接入代码 | `POST /audio/speech`，返回二进制音频 |
| MiMo `mimo-v2.5-tts` | 暂未适配 | 不再放入语音模型选择列表 |

当前不要把下面配置作为 AiChatApp 的语音模型使用：

```text

Model: mimo-v2.5-tts
```

目前它会返回 HTML 格式的 HTTP 404。这里的结论是“当前 App 尚未适配 MiMo TTS”，不是断言 MiMo 平台没有 TTS 能力。后续应单独阅读 MiMo TTS 专用文档，再实现独立协议分支。

## 六、2026-09-24 继续开发结果

### 1. 四家 TTS 协议已适配

`lib/services/tts_service.dart` 现按官方域名分发四类非流式协议：

| 厂商 | 请求协议 | 音频响应 |
|---|---|---|
| OpenAI / OpenAI 兼容 | `POST /audio/speech` | 二进制 MP3 |
| MiMo | `POST /chat/completions`，目标文本放 `assistant` 消息，音色描述放可选 `user` 消息 | `choices[0].message.audio.data` Base64 WAV |
| MiniMax | `POST /v1/t2a_v2`，使用 `voice_setting` / `audio_setting` | `data.audio` 十六进制 MP3 |
| Qwen | `POST /api/v1/services/aigc/multimodal-generation/generation` | `output.audio.url` 或 Base64 数据 |

协议识别规则：

- MiMo、MiniMax、Qwen 只有在 Base URL 为各自官方域名时才走原生协议。
- 未知域名保留 OpenAI 兼容 `/audio/speech` 语义，避免第三方代理上的 Qwen / MiniMax 模型被错误改写 endpoint。
- 普通聊天模型不再进入语音模型选择列表；模型名需明确包含 `tts`、以 `speech-` 开头，或属于 `MiniMax-Speech`。
- OpenAI `tts-1` / `tts-1-hd` 不发送不支持的 `instructions`。
- Qwen 仅 Instruct 模型发送 `input.instructions`。

官方资料：

- MiMo：https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/audio/speech-synthesis-v2.5
- Qwen：https://platform.qianwenai.com/docs/developer-guides/speech/tts
- Qwen API 参考：https://platform.qianwenai.com/docs/api-reference/speech-synthesis/qwen-tts
- MiniMax：https://platform.minimax.cn/docs/api-reference/speech-t2a-http

OpenAI 因当前网络限制未重新读取官方页面；实现沿用已有标准 `/v1/audio/speech` 二进制响应协议，并由本地协议测试覆盖。
