# 群聊功能技术实现文档

> 本文档梳理 AiChatApp 中「群聊」从数据模型 → 状态管理 → 回复调度 → LLM 生成 → UI 渲染 → 导入导出的完整技术链条，供后续开发与排障参考。

---

## 1. 概述

群聊是与私聊并行的一套独立会话体系，核心差异在于：

- **多角色共处一室**：一条群聊会话包含用户 + N 个角色成员，消息由多个发送者产生；
- **同一份上下文，各自生成**：全员共享一份对话历史，但每个角色用**自己的模型**、**自己的系统提示词（人设）**独立生成回复；
- **概率驱动的发言机制**：角色是否发言由「不说话概率」随机决定（不再依赖 LLM 插话判定），被 @ 的角色必定发言；
- **可选的引用机制**：角色发言时按「引用回复概率」引用最近其他成员的消息，引用目标只在最近 5 条内选取。

数据流总览：

```
首页(群聊入口) ──▶ GroupChatScreen
   ├─ 用户输入（含 @ 提及 / 引用）──▶ sendMessage 入库（第一阶段，不触发回复）
   ├─ 点对号 _triggerReply：按「角色指定 → 角色缺省 → 全局」解析模型
   │        └─▶ runGroupReply：概率沉默 / @ 必答 / 逐成员生成 / 合并落盘
   ├─ 长按气泡菜单：复制 / 选择 / 引用 / 记忆点 / 撤回(我方) / 删除(角色)
   ├─ 加号面板：相册 / 拍照 / 文件 / 功能检测 / 导入 / 导出 / 上下文设置
   └─ 详情页：改名 / 头像 / 简介 / 成员管理 / 成员模型 / 成员记忆 / 上下文设置 / 删除群
```

## 2. 数据模型层

### 2.1 `GroupChat`（[lib/models/group_chat.dart](file:///d:/Projects/vibecoding/AiChatApp/lib/models/group_chat.dart)）

群聊配置模型，关键字段：

| 字段 | 含义 |
|---|---|
| `id` / `name` / `avatar` / `description` | 群标识、群名、群头像(base64)、群简介（简介会拼入模型上下文） |
| `memberCharacterIds` | 角色成员 id 列表（不含用户，用户恒为成员） |
| `memberCount` | getter = `memberCharacterIds.length + 1`（含用户） |
| `contextCount` | 上下文条数：`null`=跟随全局聊天设置；`0`=无限制；`>0`=最近 N 条 |
| `silenceProbability` | **不说话概率**（默认 0.2）：每轮每个未被 @ 的角色以此概率保持沉默 |
| `quoteProbability` | **引用回复概率**（默认 0.2）：发言时以此概率引用最近其他成员消息 |
| `lastMessage` / `lastMessageTime` / `pinned` / `createdAt` | 会话列表展示与置顶排序 |

序列化兼容：`fromJson` 对 `silence_probability` / `quote_probability` 缺失时回退默认 0.2，旧数据平滑升级。

### 2.2 `Message` 复用与扩展（[lib/models/message.dart](file:///d:/Projects/vibecoding/AiChatApp/lib/models/message.dart)）

群聊复用私聊的 `Message` 模型，通过扩展字段区分多角色发言：

| 字段/类型 | 群聊中的作用 |
|---|---|
| `senderCharacterId` | 该角色消息对应的角色 id（用户/私聊为空串），气泡解析头像、取模型用 |
| `senderName` | 角色消息的发送者显示名（落库时写入 `Character.displayName`），气泡上方显示昵称 |
| `MessageType.system` | 群成员加入/移除等**事件消息**：居中灰色小气泡，不进入回复上下文 |
| `quoteContent` / `quoteSender` | 引用块（用户引用与角色引用共用同一格式） |
| `isFromUser` | getter，`sender == MessageSender.user` |

### 2.3 `Character` 模型扩展（[lib/models/character.dart](file:///d:/Projects/vibecoding/AiChatApp/lib/models/character.dart)）

- `modelId`：角色独立指定的模型 id，空 = 跟随全局聊天模型；
- `defaultModelId`：**缺省模型** id——角色未指定具体模型且全局聊天模型也未配置时的兜底，防止群聊中角色无模型而不应答；
- 序列化键 `model_id` / `default_model_id`，`copyWith`、角色包导入导出均支持。

### 2.4 `ApiModel`（[lib/providers/api_provider.dart](file:///d:/Projects/vibecoding/AiChatApp/lib/providers/api_provider.dart)）

模型配置：`id` / `displayName` / `modelName`（API 调用名）/ `baseUrl` / `apiKey` / `contextLength`。`getModelById(id)` 取模型对象；`isVisionSupported` 缓存图片能力检测结果。

## 3. 状态管理与持久化

### 3.1 `GroupChatProvider`（[lib/providers/group_chat_provider.dart](file:///d:/Projects/vibecoding/AiChatApp/lib/providers/group_chat_provider.dart)）

`ChangeNotifier`，与私聊 `ChatProvider` 分离存储：

- 内存态：`_groups: List<GroupChat>` + `_messages: Map<String, List<Message>>`（群 id → 消息列表）；
- 持久化：`SharedPreferences` 两个 key（`group_chats_v1` / `group_chat_messages_v1`），整份 JSON 序列化；
- **防抖落盘 `_persist()`**：`_persistRunning` + `_persistDirty` 标志，落盘进行中再触发只置脏位，完成后用 `do…while` 循环写干净，避免高频触发重复全量序列化。

### 3.2 群聊管理 API

| 方法 | 功能 |
|---|---|
| `createGroup(name, memberCharacterIds)` | 创建群聊（Uuid 生成 id） |
| `updateGroupName / updateGroupAvatar / updateGroupDescription` | 改名 / 换头像 / 改简介 |
| `addMembers(characterIds, names)` | 拉人进群，对**实际新增**成员生成「XX 加入了群聊」事件消息 |
| `removeMembers(characterIds, names)` | 移出成员，对**实际移除**成员生成「XX 已被移出群聊」事件消息 |
| `setPinned / deleteGroup` | 置顶 / 删除（删除时中断该群进行中的回复轮） |
| `setContextCount` | 设置上下文条数（手写重建 `GroupChat` 以支持把 override 清回 null） |
| `setSilenceProbability / setQuoteProbability` | 设置不说话概率 / 引用回复概率（手写重建保留其余字段） |

> 手写重建注意：`setContextCount` / `setSilenceProbability` / `setQuoteProbability` 重建 `GroupChat` 时必须带上全部字段，避免丢字段。

### 3.3 消息 API

| 方法 | 功能 |
|---|---|
| `sendMessage(content, quoteContent, quoteSender)` | 用户发送文本（含引用），**仅入库不触发回复** |
| `sendImageMessage / sendFileMessage` | 用户图片 / 文件，仅入库；lastMessage 分别显示 `[图片]` / `[文件] 文件名` |
| `importMessages(messages)` | 导入聊天记录追加 |
| `deleteMessage(messageId)` | 删除单条（角色消息长按），不再作为上下文 |
| `withdrawMessage(messageId)` | 撤回用户消息：`_replyGeneration++` **中断进行中回复轮** + 删除消息 |
| `_addSystemMessage` | 系统事件消息（`MessageType.system`） |

## 4. 群聊回复机制（核心）

### 4.1 两阶段触发链路（[lib/screens/group_chat_screen.dart](file:///d:/Projects/vibecoding/AiChatApp/lib/screens/group_chat_screen.dart)）

**第一阶段——发送**：输入框有文本显示「发送」，`_handleSend` → `sendMessage`（携带引用字段），只入库不触发回复。

**第二阶段——对号**：输入框为空时显示「对号」，`_triggerReply` 触发整轮群聊回复：

1. 遍历 `group.memberCharacterIds`，经 `CharacterProvider.getCharacterById` 取角色；
2. **模型解析优先级**（每角色独立）：
   ```
   角色指定 modelId → 角色缺省 defaultModelId → 全局聊天模型 selectedModelId
   ```
   模型对象经 `ApiProvider.getModelById` 获取，取不到的记入缺失名单；
3. 构造 `GroupMemberReply` 快照（纯数据、不依赖 BuildContext）：
   `characterId / name(displayName) / systemPrompt(人设) / userRelationship / activeStart / activeEnd / model / memoryPoints`（记忆点来自 `MemoryPointProvider.pointsFor(id)`）；
4. 上下文条数：`group.contextCount ?? chatSettings.contextCount`（群设置优先，null 跟随全局）；
5. 调用 `runGroupReply(..., mentionedCharacterIds: _pendingMentions)`（@ 名单解析自发送前文本中仍存在的 `@名字`）；
6. 对号可点条件：上一条消息必须是用户消息（`lastMessage.isFromUser`）。

### 4.2 `runGroupReply` 调度（[group_chat_provider.dart](file:///d:/Projects/vibecoding/AiChatApp/lib/providers/group_chat_provider.dart#L478-L611)）

**软中断**：进入时 `_replyGeneration++`，后续每次 await 返回后校验 `generation != _replyGeneration` 即丢弃（HTTP 无法取消，靠序号丢弃过期结果）。`withdrawMessage`、`deleteGroup` 也会自增该序号。

**发言名单**：
- 被 @ 的角色排最前，**必定发言**（跳过沉默判定）；
- 其余角色 shuffle 随机顺序，逐个按 `silenceProbability`（群配置，默认 0.2）判定：`random.nextDouble() < silenceRate` 则 `continue` 沉默。

> 设计演进：早期使用 `LLMService.shouldReply` 让模型判定是否插话，导致无外部指令时成员集体不说话；现改为**纯概率沉默**，发言完全由概率 + 模型生成决定。

**逐成员生成**（每角色独立请求）：
1. `_buildGroupSystemPrompt`（人设 + 群语境，见 4.4）；
2. `_buildGroupHistory`（共享历史，见 4.5）；
3. 组装输出指令（见 4.6），追加顺序固定为：防复述前缀 → @ 提示 → 引用提示；
4. `LLMService.generateMessages(model: 该角色模型, ...)`；
5. 解析出的每条消息经 `_addGroupMessage` 落库（写 `senderCharacterId` + `senderName`），**回复轮内 `persist: false`**；
6. 模拟打字耗时：`random*800 + content.length*40 + 500` ms，逐条弹出贴近群聊观感；
7. 整轮结束 `_replyingGroupId = null`，统一 `_persist()` **一次**。

### 4.3 引用机制

- 触发：`random.nextDouble() < quoteRate`（`quoteRate = group.quoteProbability`，默认 0.2）；
- 目标选取 `_pickQuoteTarget`：**只在最近 5 条消息内**随机选一条「其他成员」的文本消息（排除自己、排除系统事件、排除空内容）；最近 5 条内无可用目标则不引用；
- 生成指令追加：「你想回应群友『X』刚说的话：…请围绕这条消息回复」；
- 落库：仅该成员本轮**第一条**消息带引用块（避免连续多条都带引用显得累赘），`quoteContent/quoteSender` 与用户引用同一格式渲染。

### 4.4 群聊系统提示词 `_buildGroupSystemPrompt`

组合顺序（人设放最前保证优先级）：

1. **角色人设** `m.systemPrompt`（角色系统提示词，必拼，否则回复不贴人设）；无则用兜底模板「你是 X，正在微信群…聊天」；
2. 群名 / 群简介（简介进入模型上下文，角色按简介语境对话）；
3. 你们的关系（`userRelationship`）；
4. 用户长期记忆（`memoryPoints` 逐条 `- ` 列举）；
5. 当前时间（YYYY-MM-DD HH:mm:ss）；
6. 群聊回复要求：
   - 极度口语化，像真实微信群聊，允许语气词、表情包文字（如 [捂脸]）；
   - 拆分 1~3 条短消息，每条 5~15 字，最多 20 字；
   - **严禁复述、转述、总结或引用其他成员的发言内容**，不得出现「XX说……」句式；
   - 活跃时段判定：命中 `PromptBuilder.inActivePeriod` 要求保持活跃禁止道别；未命中则「时间极不合理可以沉默」。

### 4.5 历史上下文 `_buildGroupHistory`

- 按 `contextCount` 截取最近 N 条（0 = 全部）；
- `MessageType.system` → 以 `{'role':'user','content':'【群通知】…'}` 进入上下文，让角色感知成员变化；
- 用户文本 → `role: user`；用户图片 → `[用户发送了一张图片]`（文本占位，群内模型可能不支持视觉）；用户文件 → `[用户发送了一个文件：文件名]`；
- 角色消息 → `role: assistant`，content 带发送者名前缀 `$name：$content`，让模型知道是谁说的。

### 4.6 输出指令 `PromptBuilder.buildOutputInstruction`

最后一条 user 消息追加强指令（模型对最后一条 user 消息的格式遵守度最高）：

```
【系统指令】现在请以 X 的身份，回复用户最近发来的消息。你的最终回复必须且只能是一个
JSON 字符串数组，格式如 ["消息1", "消息2"]，每个元素就是你发送的一条消息。
不要输出任何解释性文字、Markdown 代码块或 JSON 对象。
```

群聊场景在指令前缀再叠加（按序）：

1. `只输出 X 自己的新内容，不要复述或转述群内其他人刚说过的话。`（防角色转述 AB 发言）
2. 被 @ 时：`用户刚在群里 @了你，请立刻回应 ta。`
3. 有引用时：`你想回应群友「X」刚说的话："…"，请围绕这条消息回复。`

## 5. LLM 服务层（[lib/services/llm_service.dart](file:///d:/Projects/vibecoding/AiChatApp/lib/services/llm_service.dart)）

- `generateMessages(model, systemPrompt, historyMessages, outputInstruction)`：组装 messages → `_fetchWithKimiFallback` → `parseMessages` 容错解析 JSON 数组；
- `_fetchWithKimiFallback`：首次失败且模型名含 `kimi` 时以 `temperature=1` 重试一次；
- `parseMessages`：优先正则提取数组，失败退兜底消息，不用 `response_format` 强制 JSON（DeepSeek json_object 有概率返回空 content）；
- `describeException`：统一异常 → 可读中文提示，供 `_lastError` 展示；
- 已移除 `shouldReply`（概率沉默机制取代 LLM 插话判定）。

### 6.4 @ 提及系统

- 输入框 `onChanged: _handleInputChanged`：用「上一条文本是否以 @ 结尾」边沿检测（`_prevEndsAt`），命中后 `Future.microtask` 延迟调用 `onMentionRequest`（同步 push 弹层不可靠；`onChanged` 仅用户编辑触发，`setText` 程序化赋值不会误触发）；
- `_onMentionRequest`：从 `memberCharacterIds` 过滤出仍存在的角色，`showCupertinoModalPopup` 弹选择面板（最大 50% 屏高），**不收起软键盘**（Cupertino 模态路由不丢输入框焦点，面板 SafeArea 落在键盘上方，选完可继续输入）；
- 选中后 `appendMention`：若文本以孤立 @ 结尾先去掉，在光标处插入 `@名字 `；`_mentionMap[名字] = 角色id`；
- 发送时 `_pendingMentions` = 文本中仍存在的 `@名字` 对应的角色 id，作为「优先且必定回复」名单传入 `runGroupReply`，用后清空。

### 6.5 长按气泡菜单

`ChatBubble.onLongPress(message, bubbleKey)` → `_showBubbleMenu`：
- **定位**：`bubbleKey.currentContext.findRenderObject()` → `localToGlobal`；菜单尺寸按项数自适应，X 方向我方在右菜单靠左、对方在左菜单靠右（越界钳制），Y 方向限制在导航栏下到输入栏上之间；
- **实现**：`OverlayEntry` 插入全屏透明遮罩 + `Positioned` 圆角面板（`Wrap` 排列按钮）；
- 菜单项：
  - 复制：`Clipboard.setData`；
  - 选择文本：对话框内 readOnly `CupertinoTextField` 长按原生选择；
  - 引用：记录 `_quoteMessage`，输入框上方出现引用条（标题「引用 我 / 引用 {senderName}」+ 原文截断 + X 清除）；
  - **保存为记忆点**：用户消息 → 存入群内**所有角色**（文案「$userName说：…」）；角色消息 → 存入该角色自己（文案「$displayName说：…」）；逐个调 `memoryProvider.addPoints`；
  - 我方消息追加「撤回」：`withdrawMessage`（中断回复轮）+ 内容回填输入框并聚焦，若撤回的是被引用消息则清引用；
  - 角色消息追加「删除」：`deleteMessage`（不再作为上下文）。

## 7. 导入导出（[lib/services/chat_records_service.dart](file:///d:/Projects/vibecoding/AiChatApp/lib/services/chat_records_service.dart)）

**导出** `buildExportZip`：zip 内含：
- `chat.json`：整体 JSON 对象（非每行），结构 `{app, app_version, character_name, export_time, message_count, messages: [...]}`；
- `images/xxx.jpg`、`files/原名`：图片/文件实体，消息 `content` 改写为包内相对路径（原文件缺失则保留绝对路径不入包）；
- 每条消息字段含 `id / is_from_user / type / content / created_at / quote_content / quote_sender`，**群聊专属字段 `sender_character_id` 与 `sender_name`**（多角色发言还原的关键）。

**导入** `importZip`：`ZipDecoder` 解包 → `_fixFileName` 修复 GBK 乱码文件名 → 必须含 `chat.json` → `_decodeText` 解码（UTF-8 优先，失败退 GBK）→ 图片/文件解到 `应用文档目录/chat_import_{时间戳}/` 并改写绝对路径 → 重建 `Message`（新 uuid、conversationId 为当前群 id），经 `sender_character_id/sender_name` 还原多角色发言，`sender` 由 `is_from_user` 决定。

## 8. 性能优化清单

| 优化点 | 实现 |
|---|---|
| 回复轮合并落盘 | 轮内 `persist: false`，整轮结束统一 `_persist()` 一次，避免上千条消息时每条都全量序列化 |
| 防抖落盘 | `_persistRunning/_persistDirty` + do…while 循环 |
| 列表隔离重建 | `Selector` 按 `getMessages` 结果 + `identical` 比较，回复轮/错误通知不重建列表 |
| 头像 Map 预计算 | 每次列表 build 一次遍历群成员构造 `avatarById`，避免逐条线性查找 |
| 图片按需解码 | `cacheWidth/cacheHeight`（240×像素密度）+ `gaplessPlayback` |
| 增量滚动 | `_lastRenderedCount` 对比，仅消息增加且不在底部时动画滚动 |
| 时间标签节流 | 相邻消息间隔 ≥10 分钟才显示 |
| 发送节流 | `_sendThrottleMs = 500` |

## 9. 关键时序（一次完整群聊回复）

```
用户输入 "大家好@小明" ──▶ 发送（第一阶段）sendMessage 入库
    │                       （@检测：onChanged 边沿检测 → @面板 → appendMention）
    ▼
点对号（第二阶段）_triggerReply
    ├─ 遍历成员 → 解析模型（指定 → 缺省 → 全局）
    ├─ 构造 GroupMemberReply 快照（含 model、人设、记忆点）
    └─ runGroupReply
        ├─ _replyGeneration++（软中断旧轮）
        ├─ 被 @ 角色排最前（必答），其余 shuffle + 按 silenceProbability 随机沉默
        ├─ 对每位发言者：
        │    ├─ _buildGroupSystemPrompt（人设 + 群语境）
        │    ├─ _buildGroupHistory（共享历史 + 【群通知】）
        │    ├─ 组装输出指令（防复述 → @提示 → 引用提示）
        │    ├─ LLMService.generateMessages（该角色模型）
        │    └─ _addGroupMessage 逐条落库（persist:false）+ 模拟打字延迟
        └─ 整轮结束：_replyingGroupId=null，_persist() 一次
```

## 10. 设计决策与演进记录

| 决策 | 理由 / 演进 |
|---|---|
| 概率沉默取代 LLM 插话判定 | `shouldReply` 的 LLM 判定在无外部指令时导致成员集体不说话；改为每角色按 `silenceProbability`（默认 20%）随机沉默，被 @ 必答 |
| 引用目标限最近 5 条 | 早期在整个上下文窗口随机选，话题已过仍引用旧消息；限制窗口后引用贴近当前话题 |
| 引用概率可配置 | 从固定 40% 降为默认 20%，并放入上下文设置可调 |
| 人设必须拼入群系统提示词 | 早期 `_buildGroupSystemPrompt` 未使用 `systemPrompt` 导致回复不贴人设 |
| 输出指令防复述 | 系统提示词规则 + 「只输出 X 自己的新内容」前缀双保险，防止 C 回复出现「A说…B说…」 |
| 被 @ 用 onChanged 边沿检测 | controller 监听 + 同步 push 弹层不可靠；`Future.microtask` 延迟 + `onChanged` 仅用户编辑触发 |
| @ 面板不收起键盘 | Cupertino 模态路由不丢输入框焦点，面板 SafeArea 落在键盘上方，选完可继续输入 |
| 系统事件入上下文 | 事件消息以「【群通知】」前缀进入模型上下文，角色感知成员变化（早期不进入） |
| 事件气泡渲染 | `MessageType.system` 居中灰色小气泡，无头像/引用/长按菜单 |
| 模型三档兜底 | 角色指定 `modelId` → 角色缺省 `defaultModelId` → 全局聊天模型，防止角色无模型不应答 |
| 图片占位进上下文 | 用户图片以文本占位，群内模型可能不支持视觉 |
| 整轮合并落盘 | 回复轮内不逐条落盘，避免长聊天下每条角色消息触发全量序列化卡顿 |
