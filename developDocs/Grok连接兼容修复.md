# Grok 连接与请求兼容

APP 使用 OpenAI 兼容的 Chat Completions 接口。xAI 官方地址可填写 `https://api.x.ai/v1`，也兼容 `https://api.x.ai` 或完整 `/v1/chat/completions` 地址。Grok 模型留空地址时使用 xAI；其它模型沿用原默认地址。自建／第三方网关保留配置的主机、路径前缀及查询参数，不会把网关 KEY 转发给官方地址。

此次修复覆盖普通补全、语C流式补全、图片能力检测、表情图片标签与模型列表请求：

- Grok 不再接收 Qwen 专用的 `enable_thinking`。Grok 3 mini 的显式思考档位映射到 `low`／`high`；其余 Grok 家族使用模型默认思考方式，不发送不支持的 `reasoning_effort`。不能通过“关闭思考”强行关闭固定推理模型的思考，需选择非推理型号。
- Grok 4 系列推理型号及 Grok 3 mini 的输出额度至少为 4096 token，为包含在输出额度中的推理留空间；非推理型号保留原请求额度。此值是输出上限，实际用量以服务端 usage 为准。
- Grok 响应等待及流式读取空闲超时为 180 秒，避免慢推理被原 60 秒限制提前中断；连接阶段仍为 20 秒。普通补全的正文读取同样有超时。
- 非 200 响应保留 HTTP 状态与服务端具体错误，支持 `error` 为对象或字符串。400／422 参数拒绝、401 鉴权、403 访问权限、404 地址／模型、429 限流／额度及服务端故障分别提示；响应中回显的本次 KEY 会隐藏。流式错误事件和无正文结束不会静默当作成功。
- 在【API 设置 → 编辑模型 → 连接配置 → 测试模型连接】可用当前尚未保存的配置发起小型测试请求。会消耗实际 token；操作期间禁止重复测试，结果弹窗显示完整诊断并可复制。无需把 KEY 发给他人。

自动验证使用本机 HTTP 测试服务，无需真实 KEY，覆盖官方地址归一化、网关路径保留、全部思考档位、流式思考／正文／用量、视觉请求、错误分类及诊断弹窗。运行：

```powershell
flutter test --no-pub test/services/llm_grok_test.dart test/screens/model_connection_test.dart
```

本地协议测试不等同于真实 xAI 账号已连通。真实请求仍取决于账号权限、余额、地区和服务端支持的模型。升级 APP 后可在上述测试入口查看实际服务端原因；不需要重新填写正确的 KEY。
