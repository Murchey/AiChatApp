# AiChat 后端部署指南

本文适用于 `server_project` 的 Spring Boot 3 + Java 21 + SQLite 后端。部署前请确认你使用的是项目内的 `gradlew`/`gradlew.bat`，不要把同一个 SQLite 数据目录交给多个后端实例同时写入。

如果你只是想先跑起来，请先看 [快速开始](快速开始.md)。下面的内容用于云服务器、HTTPS 和长期运行。

## 1. 部署前准备

需要准备：

- Java 21 LTS；
- 一台 Ubuntu 服务器或 Windows 主机；
- 一个独立的数据目录；
- 至少 32 个字符的随机 `AICHAT_TOKEN_PEPPER`；
- 首次管理操作使用的随机 `AICHAT_BOOTSTRAP_ADMIN_TOKEN`。

生产环境必须使用 HTTPS。推荐让 Caddy 或 Nginx 负责 TLS，Spring Boot 只监听本机的 8080 端口。

## 2. 构建 JAR

最简单的本机部署方式：

```powershell
.\scripts\deploy.ps1
```

Linux/macOS：

```bash
./scripts/deploy.sh
```

这两个脚本会运行测试、构建 JAR，并复制到一个独立目录。它们不会自动修改云服务器或防火墙；云服务器仍按下面的 systemd 步骤配置。

在仓库的 `server_project` 目录执行：

```bash
./gradlew test bootJar
```

Windows PowerShell：

```powershell
.\gradlew.bat test bootJar
```

生成文件：

```text
build/libs/aichat-backend.jar
```

可以把这个 JAR、`deploy/`、`data/stories/` 和配置文件复制到部署机；不需要复制 `build/classes` 或 `.gradle` 缓存。

## 3. Ubuntu 直接启动

安装 Java 并创建服务用户和目录：

```bash
sudo apt update
sudo apt install -y openjdk-21-jre-headless
sudo useradd --system --home /opt/aichat --shell /usr/sbin/nologin aichat || true
sudo mkdir -p /opt/aichat/data /etc/aichat
sudo chown -R aichat:aichat /opt/aichat
```

将 JAR 放到 `/opt/aichat/aichat-backend.jar`，创建 `/etc/aichat/aichat.env`：

```ini
AICHAT_DATA_DIR=/opt/aichat/data
AICHAT_PORT=8080
AICHAT_TOKEN_PEPPER=替换为随机的至少32字符密钥
AICHAT_REQUIRE_TOKEN_PEPPER=true
AICHAT_BOOTSTRAP_ADMIN_TOKEN=替换为另一条随机管理密钥
AICHAT_INVITE_REQUIRED=true
AICHAT_FEATURE_STORIES=true
AICHAT_FEATURE_ADMIN_PUBLISH=true
AICHAT_FEATURE_SYNC=false
AICHAT_FEATURE_COMMENTS=false
AICHAT_FEATURE_LLM_RELAY=false
```

先以前台方式验证：

```bash
set -a
. /etc/aichat/aichat.env
set +a
java -jar /opt/aichat/aichat-backend.jar
```

另开终端检查：

```bash
curl --fail http://127.0.0.1:8080/api/health
curl --fail http://127.0.0.1:8080/api/version
```

首次启动会在数据目录创建 SQLite 文件并运行全部 Flyway 迁移。确认健康检查成功后按 `Ctrl+C` 停止前台进程。

## 4. Ubuntu 使用 systemd

复制模板并按实际路径修改：

```bash
sudo cp deploy/aichat.service /etc/systemd/system/aichat.service
sudo systemctl daemon-reload
sudo systemctl enable --now aichat
sudo systemctl status aichat
```

实时查看日志：

```bash
sudo journalctl -u aichat -f
```

模板默认使用：

```text
User/Group: aichat
JAR: /opt/aichat/aichat-backend.jar
数据目录: /opt/aichat/data
环境文件: /etc/aichat/aichat.env
```

如果修改了 JAR 或环境变量：

```bash
sudo systemctl restart aichat
curl --fail http://127.0.0.1:8080/api/health
```

## 5. HTTPS 反向代理

### Caddy

复制 `deploy/Caddyfile.example`，把域名替换为自己的域名：

```text
example.com {
    encode zstd gzip
    request_body { max_size 4MB }
    reverse_proxy 127.0.0.1:8080 { flush_interval -1 }
}
```

Caddy 会自动申请和续期证书。确认域名 DNS 已指向服务器后重载 Caddy：

```bash
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
curl --fail https://example.com/api/health
```

### Nginx

复制 `deploy/nginx.conf.example`，补上域名、证书路径和日志配置。必须保留：

- `proxy_http_version 1.1`；
- `proxy_buffering off`，保证 LLM SSE 不被缓存；
- `client_max_body_size 4m`；
- `proxy_read_timeout` 大于后端中继总期限。

公网只开放 80/443。不要把 8080 直接暴露到公网，也不要把 SQLite 数据目录映射成网络共享。

## 6. Windows 本机部署

安装 Java 21，进入 `server_project`，先构建：

```powershell
.\gradlew.bat test bootJar
```

使用独立数据目录和环境变量启动：

```powershell
$env:AICHAT_DATA_DIR = 'D:\AiChatData'
$env:AICHAT_PORT = '8080'
$env:AICHAT_TOKEN_PEPPER = '替换为随机的至少32字符密钥'
$env:AICHAT_REQUIRE_TOKEN_PEPPER = 'true'
$env:AICHAT_BOOTSTRAP_ADMIN_TOKEN = '替换为另一条随机管理密钥'
New-Item -ItemType Directory -Force $env:AICHAT_DATA_DIR | Out-Null
java -jar .\build\libs\aichat-backend.jar
```

也可以使用开发启动脚本：

```powershell
.\scripts\run.ps1 -Port 8080 -DataDir D:\AiChatData
```

Windows 防火墙只开放实际需要的端口。使用内网穿透时，将隧道指向 `127.0.0.1:8080`，App 中填写隧道提供的 HTTPS 地址；不要把数据库文件或管理令牌暴露给隧道访问者。

## 7. 初始化管理员和设备邀请码

服务启动后，使用 bootstrap 管理令牌生成普通用户邀请码：

PowerShell：

```powershell
.\scripts\generate-invite.ps1 `
  -BaseUrl 'https://example.com' `
  -AdminToken $env:AICHAT_BOOTSTRAP_ADMIN_TOKEN `
  -MaxUses 1 `
  -ExpiresInHours 24 `
  -Role USER
```

生成管理员设备邀请码：

```powershell
.\scripts\generate-invite.ps1 `
  -BaseUrl 'https://example.com' `
  -AdminToken $env:AICHAT_BOOTSTRAP_ADMIN_TOKEN `
  -Role ADMIN
```

bootstrap 令牌只用于初始化和紧急管理。日常管理应使用兑换得到的 ADMIN 设备令牌，并在确认管理员设备可用后轮换或撤销 bootstrap 令牌。

## 8. 发布故事

先准备符合故事 JSON 格式的文件，在 `server_project` 中验证：

```powershell
.\scripts\validate-story.ps1 -Path .\data\stories\example.json
```

发布到已配置的服务：

```powershell
.\scripts\publish-story.ps1 `
  -Path .\data\stories\example.json `
  -BaseUrl 'https://example.com' `
  -AdminToken $env:AICHAT_BOOTSTRAP_ADMIN_TOKEN
```

Linux 使用：

```bash
./scripts/validate-story.sh data/stories/example.json
./scripts/publish-story.sh data/stories/example.json https://example.com "$AICHAT_BOOTSTRAP_ADMIN_TOKEN"
```

发布后检查：

```bash
curl --fail 'https://example.com/api/stories?limit=20'
```

故事版本不可变；新版本发布前不会覆盖线上旧版本。校验失败、版本冲突或重复发布时，先读取当前草稿和版本，不要盲目重试覆盖。

## 9. 在 App 中连接

在 App 的“发现 → 故事线社区 → 设置”中选择“自建服务器”，填写：

1. HTTPS 服务地址（例如 `https://example.com`）；
2. 端口（如果地址已包含标准 HTTPS 端口可留空或使用 443）；
3. 设备邀请码；
4. 连接测试并保存。

App 会先访问 `/api/health` 和 `/api/version`，再兑换设备令牌。服务端不可用或版本不兼容时，App 保留本地/静态故事来源，不会删除已有缓存。

## 10. 可选模块

默认关闭的模块只能在明确需要时开启：

```ini
AICHAT_FEATURE_SYNC=true
AICHAT_FEATURE_COMMENTS=true
AICHAT_FEATURE_LLM_RELAY=true
```

开启 LLM 中继前还要准备模型目录，并通过额外 Spring 配置加载：

```bash
java -jar /opt/aichat/aichat-backend.jar \
  --spring.config.additional-location=file:/opt/aichat/config/llm.yml
```

公网启用同步、评论或 LLM 中继前，应先阅读 [可选模块指南](optional-modules.md)，并确认反向代理限流、HTTPS、日志脱敏和备份策略。

## 11. 备份、升级和回滚

升级前：

1. 停止服务；
2. 备份 SQLite 文件、`data/stories/`、环境文件模板和当前 JAR；
3. 保留原 `AICHAT_TOKEN_PEPPER`，否则旧设备令牌无法验证；
4. 替换 JAR 后启动，让 Flyway 自动执行新迁移；
5. 检查 `/api/health`、`/api/version` 和故事列表。

回滚时不要让旧 JAR 直接打开已经升级过的数据库；应恢复与旧 JAR 匹配的数据库备份。不要手工修改已执行的 Flyway 文件。

## 12. 常见问题

### `AICHAT_TOKEN_PEPPER` 启动失败

生产配置需要至少 32 个字符，并设置 `AICHAT_REQUIRE_TOKEN_PEPPER=true`。本地 M0 健康检查可以关闭强制校验，但不要用于公网部署。

### App 提示超时

先在同一网络执行 `curl https://域名/api/health`，再检查 DNS、防火墙、隧道和反向代理。不要把超时简单改成无限等待；后端和 App 都有明确请求期限。

### 故事列表为空

确认 `AICHAT_FEATURE_STORIES=true`、故事已成功发布，并检查：

```bash
curl --fail https://域名/api/version
curl --fail 'https://域名/api/stories?limit=20'
```

### SQLite 被锁定

同一个数据目录只能运行一个服务实例。停止重复启动的 JAR 和直接操作数据库的脚本后再重试。
